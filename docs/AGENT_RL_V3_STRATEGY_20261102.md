# 小懿 2.0：目标稳定、场景变化的工具学习实验

日期：2026-11-02。产品方向称“小懿 2.0”，代码和证据目录使用实验版本 V3。

## 本轮要回答什么

同样是“读取港口、能源和交通，完成评估与能碳比较，核验并交付报告”，当中途数据过期、条件更新、请求超时、回执丢失，甚至几种情况同时出现时，小懿能否学会依据反馈调整操作？在相同起点、相同工具和足够强的继续 SFT 对照下，RL 是否改善成功率、恢复能力或训练数据效率？

这是需要验证的假设。业务复杂不自动意味着 RL 胜出；SFT 也能学习故障恢复。未来适配能力依赖正确的接口契约、可交互环境、可信奖励和重新学习的机会，不能解释为对任何新系统自动兼容。

## 算法选择：可靠性优先

会议收录只是筛选入口。审查内容包括公式与代码的一致性、实验和消融、适用任务、计算成本、可复现性及已知限制。不把作者的提升数字当作我们本地的证据；目前也没有足够的独立复现证据，宣布某个算法“所有候选里最可靠”。

1. **主线：Dr.GRPO 的简洁优化方法。** 来源为 COLM 2025《Understanding R1-Zero-Like Training: A Critical Perspective》。其去除轨迹长度和组内奖励标准差归一化的做法，使本地实现与梯度检查较直接。采用它是本项目的工程选择，不是对所有 RL 算法的排名。[论文](https://arxiv.org/abs/2503.20783)；[作者代码](https://github.com/sail-sg/understand-r1-zero)。
2. **较新的单独处理组：ExGRPO 启发的经验复用。** 已核实 ICLR 2026 正式收录。成功探索的轨迹可在后续学习中复用，并记录采样时概率。原研究涵盖 1.5B–8B 的推理模型，但不是港航多工具任务，也不直接证明优于我们的继续 SFT。[正式会议记录](https://proceedings.iclr.cc/paper_files/paper/2026/hash/15a296dc96baa12aaef4facdd391161f-Abstract-Conference.html)；[论文原文](https://arxiv.org/abs/2510.02245)。
3. ACL 2024 的 RLOO 是可考虑的简单基线；本轮不同时堆叠更多算法。DAPO 存在两个不同的同名论文，已区分；大规模 GPU 配方不直接移植到本机。

ExGRPO 官方仓库固定到提交 `01f4ae066249e6965ce0d5512ccdf99a12895c74`。相关文件和 SHA256 保存在 `.codex_artifacts/agent-rl-v3-20261102/research/`，只阅读核对，不执行其中的安装脚本。特别核对 `mix_core_alg.py` 的 replay 权重变换。

还发现一个需要保留的审查意见：ExGRPO 附录 E.1 描述了从测试集中抽取约 2.2k 样本监控训练。它同时说明未采用 early stopping；这不足以据此指控其结果无效，但不能据此确认严格独立的开发/最终测试隔离。本项目使用独立开发任务，最终测试在选择冻结后再开启，不沿用这一设置。[附录原文](https://arxiv.org/html/2510.02245v2#A5.SS1)

## 实际怎样训练

大模型像操作员，环境像训练用的港航系统，harness 把模型选择的工具执行并返回结果，RL 根据执行得分调整模型参数。

本次用已有 Qwen3-1.7B，更新其最后四层注意力中的 229,376 个 LoRA 参数。模型在每个状态从 13 个明确显示的工具/参数候选中选择一个；harness 不替它选正确答案。此阶段验证工具选择、预设参数组合识别和多步恢复，**尚不验证任意 JSON、连续参数生成、自由长文推理或任意桌面按钮操作**。

一次 RL 更新的顺序：同一任务采样四条完整轨迹 → 从实际环境结果计算回报 → 用回报减去组平均，得到每条轨迹的相对优势 → 用动作的概率和优势计算损失 → 反向传播并更新 LoRA → 保存权重、优化器、随机状态及完整原始记录。

动态事件包括：能源读取超时、港口缓存版本过期、计算后港口条件更新、能碳写入响应丢失、核验时交通状态更新，以及部分任务要求恢复模拟时钟。最终目标始终是最新有效证据齐全且核验通过的报告。全部为可重置合成环境，不调用真实港口生产接口。

奖励由最终完成、失败、调用成本、可避免错误和无进展重复调用组成。进度塑形在终止时回到零，检查其和式，防止模型反复读取刷分。注入的故障与模型错误分别记录。

## 对照设计

| 组别 | 学习方式 | 作用 |
| --- | --- | --- |
| A 规则 | 根据同样可见的版本和回执执行 | 确认任务可解，展示工程基线 |
| C 共同 SFT | 上轮最强继续 SFT 权重 + 共同的新环境示范适配 | 所有新处理组的同一起点 |
| D SFT＋RL | 在线采样完整轨迹，采用 Dr.GRPO 风格动作损失 | 检验加入 RL 的作用 |
| E 继续 SFT | 对 D 采样到的全部状态提供正确操作，包括失败状态 | 强监督对照，避免故意弱化 SFT |
| F SFT＋RL＋经验复用 | D 的目标加 ExGRPO 启发的历史成功轨迹复用 | 单独检验经验复用是否值得 |

D/E 使用相同状态位置数量、相同更新次数、同一初始化和同一动作温度；E 享有正确示范标签，D 不读取标签。分别记录标签数量、环境交互量、训练时间和缓存命中，不将相等更新次数宣传成相等实际算力。E 使用 D 收集的数据，是带 oracle 纠错的继续 SFT，而不是声称完全相同数据来源成本。

日志解释：E 更新摘要里的 `returns` / `successes` 描述它消费的 D 组训练轨迹，不代表 E 模型自行执行的表现。E 的真实完成率只来自其独立运行的 `validation/E_more_sft-*.json`。绘图程序不会把复用训练轨迹的成功率画成 E 的性能。

F 的本地改动：沿用固定任务日程，不实现原文的跨任务难度分桶和任务淘汰；从同任务的部分成功采样组保存成功轨迹，选择当前模型平均负对数概率最低的一条；每组最多一条历史轨迹，其余重新采样；保留实际行为概率，并对 replay 使用 `w/(w+0.1)`。因此称为 **ExGRPO 启发的动作策略适配**，不能写成完整复现原版 ExGRPO。裁剪、经验筛选和变换都会影响统计性质，不宣称整个实现是无偏估计。

## 执行步骤与门槛

1. **保留第一轮。** 实验004、所有负结果和验收展示包不改写，新建实验005-pilot。新起点取上轮最强 E384，并明确其选择已经参考过上一轮结果；上一轮测试集不再作为新独立测试。
2. **完成环境与算法检查。** 覆盖正确恢复、过期证据拒绝、未知写入不盲目重发、不能提前交付、塑形不能刷分、梯度方向、replay 变换的有限差分，以及断点续训。
3. **本机可行性试跑。** 12 个训练任务、4 个开发验证任务、12 个封存组合测试任务、16 个封存旧能力任务。共同适配 64 次单状态更新；D/E/F 各 8 次轨迹组更新，每组 4 条、每条最多 20 步。小试只重复其中 4 个任务以检查复用链路，不冒充充分训练。开发验证显示全部预登记节点，不挑最好节点来宣布优势。封存测试和旧能力任务此时不跑。
4. **根据小试确定正式计算预算。** 检查成功探索是否存在、组间回报是否有差异、梯度和 KL 是否正常、经验是否真正复用、本机内存和每轮耗时。若需要调整任务或训练参数，另建实验并保存旧小试，不覆盖失败记录。若没有成功经验，F 应如实报告复用为零。
5. **正式独立验证。** 冻结任务生成器与预算后，用至少 3 个训练种子、更多任务和独立组合测试；三个处理组必须完整跑完。采用开发集选择权重，选择完再一次性开启新的最终测试。封存原能力任务和新构建通用问答测试检验遗忘，不能拿它们做训练标签。
6. **完成展示。** 汇总任务成功率随复杂程度变化、异常恢复率、训练回报、真实验证成功率、KL/熵/梯度、相同交互预算与示范标注成本、能力保持及成败实例。展示各个种子与不确定性；简单任务无优势、规则满分、RL 退化等结果照常保留。最后再把通过测试的权重接回本地多系统，验收一条实际模型驱动的指令闭环。

不能把小试几个任务的提升当作统计显著；不能在测试集上反复选算法，不能预先保证 RL 必赢。真正可向专家展示的能力，是提出可检验假设、实现可信的训练和对照、找到优势边界并能解释失败。

## 数据与恢复

“封存测试”指不对被比较的学习模型运行测试、不据测试性能选择训练设置。对任务生成器的结构、哈希、规则可解性和防提前交付的单元检查，会覆盖所有分区；这类环境质量检查不产生被比较模型的测试分数。

## 系统功能补齐与真实接口边界

为避免语言模型学到恢复动作后无接口可用，增加以下各组共用的能力：

| 系统 | 新增能力 | 已完成的验证 |
| --- | --- | --- |
| 能碳驾驶舱 | 带版本前置条件的双方案计算、SQLite持久回执、同请求幂等、按请求读回 | 7项新增测试；连同相关回归共31项通过；实际API计算、重复请求、重启后读回、冲突参数和过期版本拒绝 |
| 港口数字孪生 | 捕获公开数据回放锚点、绑定该锚点的情景评估、持久回执、超时/版本检查 | 7项新增测试；相关回归合计14项及6个子测试通过；实际API重复请求返回同一回执 |
| 小懿工具适配 | 提交前保存请求意图；未知响应通过显式核验动作读回；保留每一步原生响应 | 4项测试通过；三系统API合同探针在读取超时和真实计算后隐藏响应的情况下，8步完成报告 |

三系统探针使用规则选择动作，明确记录`model_used=false`，只证明接口和harness能闭环，不属于LLM或RL效果。新V4模型驱动验收入口为`scripts/run_agent_native_v4.py --mode model --adapter ...`，没有规则回退。训练仍在可重置合成环境进行。

当前原生适配支持读取超时和实际计算后的响应丢失。港口条件变更、交通版本变更等训练扰动尚未全部映射为真实系统事件；原生V4时钟控制尚未验收，入口会明确拒绝这些任务。不能把合成扰动说成现场事件。港口源策略声明摘要与实际加载摘要的既有差异继续显示在报告，不由本次接口升级掩盖。

新接口使用独立本机实验进程（能碳18809、港口18801），原服务18808/18800保留。所有计算仍为公开数据回放和离线评估，没有生产调度授权。能碳“版本”是策略/数据文件元信息的缓存失效标识；港口上下文包含实际加载模型与数据摘要，并固定回放位置。不同系统的地点、时间轴和数据来源仍分开说明。

## 向专家说明的方法边界

本轮不是“从零、无示范地训练自主智能体”。共同SFT和课程初始化都使用了参考路径，这些准备成本必须计入。D/F的区别是额外策略更新根据执行回报进行，不再为每个访问状态提供正确操作标签；E则获得这部分额外标签。标签数是成本代理量，未测量人工标注工时，也不能据此声称实际节省了多少费用。环境、验证器、课程和工具接口的开发同样需要投入。

每个新采样组只做一次优化器更新，因此D在当前设置下的新样本重要性比率通常约为1，PPO式裁剪大多不会生效。这仍是组相对策略梯度，但不能宣称已经验证了多轮PPO裁剪带来的稳定性。F的历史轨迹可能有不同的行为概率；记录比率并按文献思想做权重变换，不等于解决了所有跨状态分布偏差。

正式验证应将“未见扰动组合上的从头完成率”列为主指标，并分别展示调用成本、错误恢复和旧任务保持。若对多个算法、多个指标做优效推断，需要处理多重比较；重用同一模板的任务不能简单当作完全独立样本。正式阶段至少显示每个训练种子的结果及配对任务差异，预先冻结选权重规则和预算，再打开独立测试。当前4个开发任务只用于可行性诊断。

可以向专家这样解释研究价值：**港航系统日益自动化后，业务目标仍然是安全、有效且可追溯地完成作业，但可行路径会随设备、数据和接口状态变化。本项目探索让语言模型利用可验证的执行反馈改善跨系统决策和异常恢复，并用强SFT对照检验收益及代价。其价值是建立可以持续试错、评估和改进的训练机制；是否在当前任务上优于SFT，由独立实验决定。**
