# 小懿AI 对标顶级港航助手：差距、已执行升级与后续路线

更新日期：2026-07-26

## 结论

持续升级已把系统从“单轮可追溯 RAG”提升为“可审计的多轮、复杂问题、
证据冲突、主张对齐和决策就绪助手”，但仍不能声称达到成熟商业产品的完整水平。当前
最强的是证据治理、可复现基准和失败关闭；主要短板仍是授权法规全文、真实
港口实时连接、外部盲测和生产级人工工作流。

## 本轮按步骤完成

1. 建立历史感知的问题分析层，输出独立问题、子问题、辖区、日期、复杂度与
   检索查询，避免把全部聊天历史直接拼入检索。
2. 为复合问题分别执行证据策略；有证据的子问题回答，无证据、条款越界或
   实时状态子问题单独拒答。
3. 增加回答后引用校验，检查 `[E#]` 是否存在、是否为 supporting 证据，并
   返回逐项覆盖率；该校验不冒充语义蕴含或法律正确性证明。
4. 修复 Markdown 切块丢失文档总标题的问题，使每个章节保留主题上下文；
   扩库后的同名“来源定位/问答边界”章节不再挤占专业主题。
5. 增强中国法规日期边界排序，事实日期与 `effective_from/effective_to`
   一致的来源优先；v1 门禁收紧为辖区、日期、实时和拒答全部 100%。
6. 新增美国、欧盟、英国、澳大利亚、日本、鹿特丹及 Paris/Tokyo MoU 等
   8 份官方来源目录或摘要；明确它们只用于导航或公开事实，不当作授权全文。
7. 新增 v2 困难集 60 题：20 题多轮、20 题复杂分治、20 题对抗边界；当时
   与 v1 合计 120 题，两套均由仓库维护且开发可见。
8. 将 v1、v2 的数据、索引、来源注册表和核心代码哈希纳入版本化报告与一致性检查。
9. 新增证据健康与决策就绪层：区分可采用、需人工复核、部分就绪、需澄清、
   需实时数据、需官方全文、证据冲突和仅限沙箱，并返回风险与下一步动作。
10. 新增 v3 决策保障 30 题；与 v1、v2 合计 150 题。
11. 修复单段回答证据编号固定写成 `[E1]` 的错位问题，返回完整的有界知识
    分块供逐项核对；新增确定性主张—证据词面对齐及数字、日期、量值完整性门禁。
12. 新增 v4 主张—证据对齐 20 题；与 v1、v2、v3 合计 170 题，并将
    数据、索引、来源注册表和核心代码 8 项工件进行 SHA-256 固化。
13. 新增面向短口语问法的日常意图扩展，补充能源削峰、船舶泊位、堆场闸口、
    班组客户与系统协同 4 份内部作业问答；短问法仍沿用严格证据门禁，模糊
    “怎么办”先追问业务对象，实时状态没有验证连接器时继续失败关闭。
14. 新增 v5 日常运营固定集 60 题，能源、船舶泊位、堆场闸口、班组协同、
    单证和设备各 10 题，另设 3 个澄清/实时数据边界用例；与 v1-v4 合计
    230 题。
15. 建立 15 个业务域 × 26 种问题形式的问题全集，生成 390 个意图单元、
    780 条正式/日常矩阵问法，并盘点 863 个知识主题、278 个直接回答主题和
    1,997 条显式或派生表达；该目录用于缺口治理，不冒充自由语言全覆盖率。
16. 新增港口减碳、安全保安与环境、商务多式联运与专业货类、管理KPI与
    系统、航海气象与工程 5 份直接回答知识包，并增加 v6 分域固定题 30 题及
    5 个澄清/实时/官方全文边界；v1-v6 合计 260 题。

- 知识快照：129 份文档、882 个分块、68 份官方核验来源；授权官方全文/正式
  摘录仍为 0，完整性声明为 `partial_auditable_coverage`。
- v1 测试分区：Hybrid Hit@1/3/5 = 100%/100%/100%，MRR 1.0000；
  BM25-only Hit@1/3/5 = 95.83%/95.83%/95.83%，MRR 0.9583。
- 官方要求、Top-5 官方纯度、证据双哈希、辖区路由、日期切换、实时边界和
  无依据阻断均为 100%；策略项 11/11。
- v2：多轮 20/20、复杂分治 20/20、对抗边界 20/20。
- v3：真实问答决策就绪 14/14；冲突、新鲜度和失败关闭保障 16/16。
- v4：引用角色 6/6、主张—证据词面对齐 6/6、数字/日期/量值完整性 8/8。
- v5：能源、船舶泊位、堆场闸口、班组协同、单证和设备六类各 10/10；
  模糊问题澄清与实时数据失败关闭 3/3。
- v6：15 个业务域正式/日常固定题 30/30；模糊问题、实时数据和官方全文

这些是开发可见的固定仓库验收指标，不是回答准确率、法律正确率、第三方
盲测、语义蕴含证明、港口生产 KPI 或线上 SLA。

## 下一阶段执行顺序

1. **授权全文层**：在许可允许时接入法规/公约正式全文或内部授权制度，
   建立条款 ID、版本谱系、修订差异和引用页码；未获授权前保持条款级拒答。
2. **真实只读连接器**：优先接 AIS/VTS、PCS/TOS 或港口开放 API 的只读
   测试环境，校验观测时间、质量码、延迟和主体标识，再开放实时问答。
3. **检索模型升级**：在现有 Sparse/BM25 对照之外加入可离线复现的向量召回
   与交叉编码重排，并用新增困难检索集检验，不以模型名称代替效果。
4. **外部评价**：邀请调度、船务、海事合规人员制作未见题集，盲评正确性、
   可操作性、引用充分性、澄清质量和误拒答率。
5. **对话与任务体验**：在前端显式展示“我如何理解了追问”、子问题完成度、
   证据缺口和需人工确认的下一步，补充中英双语压力测试。
6. **生产治理**：加入连接器级熔断、权限最小化、审计告警、知识过期监控、
   红队回归和版本回滚；现场试运行后再定义 SLA。
