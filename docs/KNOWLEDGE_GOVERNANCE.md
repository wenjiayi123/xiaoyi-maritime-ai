# 小懿AI 知识库治理规范

## 1. 目的与适用范围

本规范适用于小懿AI的知识资料采集、来源登记、待审核隔离、索引发布、证据问答和定期复核。目标不是声称知识“绝对正确”，而是让每个专业结论尽可能可检索、可追溯、可版本化、可复核，并在证据不足时拒绝编造。

## 2. 库存口径与运行时状态

截至 2026-07-26 的当前快照为：

- 129 份已登记知识文档；
- 882 个检索片段；
- 68 份经发布机构页面核验的来源资料，共 264 个片段；
- 上述官方来源资料分为摘要/发布方指南、目录/标准元数据与授权全文/摘录，三者不得混用；
- 当前授权全文/正式摘录数量为 0，因此条款、罚则、限值、时限和豁免问题必须拒答并返回官方定位入口；
- 61 份项目内部整理资料；
- 0 份未登记来源文档。

以上数字只是文档编写时的快照，不得作为长期固定值。正式监控、测试和审计必须以运行时 `GET /api/knowledge/status` 的结果为准，并可用以下接口进一步核对：

- `GET /api/knowledge/sources`：查看当前已索引来源、来源分级和文档校验哈希；
- `GET /api/knowledge/sources?official_only=true`：只查看已登记为官方的来源；
- `GET /api/knowledge/catalog`：查看 24 个专业大类、96 个主题的覆盖路线图和官方资料要求；
- `GET /api/knowledge/authority-coverage`：查看 41 个权威来源族的已索引、待补齐和许可隔离状态；
- `POST /api/knowledge/search`：核对检索命中、覆盖度、来源质量和证据哈希。

数量增加不等于质量提升。监控时应同时关注 `official_verified_documents`、`internal_curated_documents`、`unregistered_documents`、`registry_version`、`index_sha256` 和 `index_built_at`。

## 3. 来源分级

### 3.1 项目内部整理资料

当前 61 份知识文档的来源类型为 `internal_curated`，并标记为非官方、未经独立核验。这类资料可用于术语导航、业务问题拆解、培训和一般性检索，但不得被展示为法规原文、国家标准全文、监管机构结论或某港口已生效的现场制度。其中 `54`—`59` 提供原有 144 条日常专业问答，`119`—`122` 补充能源削峰、船舶泊位、堆场闸口、班组客户与系统协同等 63 个高频操作主题；`123`—`127` 再补充港口减碳、安全保安与环境、商务多式联运与专业货类、管理KPI与系统、航海气象与工程等 69 个直接回答主题。每条均以单独“直接回答”切片入库。

若内部资料与有效的官方原文、现场管理制度或经授权生产数据冲突，应以后三者中当前有效且适用的证据为准，并对内部资料发起修订或下线。

## 4. 来源元数据和完整性

每份待发布知识资料至少应登记：

| 字段 | 治理要求 |
| --- | --- |
| 来源 URL | 应指向原始发布页、法规库、标准目录或经授权内部系统；不得用搜索结果页替代原始来源。 |
| 机构 | 记录正式发布机构、资料所有者或内部责任部门。 |
| 版本 | 记录版本号、标准号、文号、发布日期或修订状态；不得只写“最新版”。 |
| SHA-256 | 对项目内实际入库的文档和每个索引片段计算哈希，用于变更检测和审计；哈希只能证明内容一致性，不能单独证明内容真实或有效。 |
| 复核日期 | 记录最后复核日期、复核人、复核结果和下次复核日期。法规、安全与合规资料在每次高风险使用前还应再次核对有效性。 |
| 授权与许可 | 记录公开使用条款、内部授权范围或标准全文的使用限制。 |
| 辖区与内容范围 | 登记 `jurisdictions`、`content_scope` 与 `legal_force`，明确资料能否支撑当地规则、条款级回答或仅能定位。 |
| 生效与失效 | 登记 `effective_from`、`effective_to`、`last_verified_at`、`review_due_at` 与更新频率。 |

来源元数据发生变化、URL 失效、版本被替代、哈希不匹配或超过复核日期时，应将该来源标记为待复核，不再把它作为当前官方结论的唯一证据。

## 5. 严格证据模式

专业问答默认使用严格证据模式，应遵守以下原则：

1. 专业陈述必须来自当前索引命中，不得把通用生成内容伪装成知识库证据。
2. 命中必须具备已登记来源、文档哈希和片段哈希，并达到当前的问题覆盖门槛。
3. 回答应同步返回 `grounded`、`coverage`、`source_quality` 和证据列表，让使用者看到来源机构、URL、版本和哈希。
4. 证据缺失、覆盖不足、来源未登记或哈希异常时，必须返回拒答，并说明需要补充的业务对象、版本或资料。
5. 闲聊可以保留，但不得因闲聊模式绕过专业知识证据门槛。
6. 用户把 `strict_evidence=false` 也不能绕过法规、安全、危险品、环保、边境或处罚类问题的官方证据门槛。
7. 客户端提交的外部证据不得自行把 `verification_status` 声明为 `live_read`；只有服务端受信只读连接器产生并带关联标识与读取时间的结果可以形成实时事实。
8. 支持证据应计算复核新鲜度；官方来源复核日期缺失、已到期或异常时，回答只能标记为“需人工复核”，不得展示为无条件可采用。
9. 同主题、同辖区证据出现强状态极性冲突，或同一来源出现版本与文档哈希分歧时，必须阻断决策就绪状态并返回冲突证据编号。
10. 专业回答应同时返回决策就绪度、风险级别、阻断原因和下一步动作；这些字段只说明当前证据链能否推进，不替代岗位授权或现场审批。

## 6. 法规、标准、安全与合规的官方来源门槛

对法规适用性、强制性标准、作业安全、危险品、海事报告、消防、环保、通关、计费、客户承诺或生产执行建议，单独的内部整理资料不足以支撑最终结论。这类问题的发布或执行前门槛为：

1. 检索时应使用官方来源过滤，并确认 `official=true`、`source_quality=official_verified`。
2. 来源 URL 必须指向当前发布机构或标准发布方，机构、版本和复核日期不得缺失。
3. 必须核对适用法域、适用对象、生效日期、废止状态、过渡条款和当地补充要求。
4. 如当前只索引了目录元数据或官方页面摘要，而结论依赖原文条款，应拒绝给出最终合规结论，直到获得有权使用的完整原文。
5. 所有高风险结论和对外发布内容必须由具备相应职责的人员复核；AI 证据命中不等于已获得执行授权。
6. 检索先按辖区、问题日期、内容范围和复核状态过滤，再按匹配度排序；全球公约不得自动外推为某一国家或港口的现行本地要求。
7. 生态环境法典等未来生效或过渡文件必须使用问题日期路由，不能把未来文本当作当前已经生效，也不能在废止日后继续引用被替代文本。

## 7. 附件待审核隔离流程

用户通过 `POST /api/knowledge/intake` 提交的文本、Markdown 或 CSV 资料只进入 `data/kb_pending` 待审核区，不能把附件正文直接拼接到问答上下文。

暂存阶段的固定边界为：

- 清洗文件名并限制允许的文本类型和内容大小；
- 对暂存内容计算 SHA-256；
- 状态固定为 `pending_review`；
- `official_claim` 只是提交者声明，必须同时保持 `official_claim_verified=false` 和 `official=false`；
- 暂存项必须保持 `indexed=false` 和 `eligible_for_index=false`；
- `GET /api/knowledge/intake` 只列出待审核元数据，不把附件正文作为知识证据返回；
- 系统不提供未经审核的自动发布、自动入索引或自动标记官方接口。

重复内容、同名文件或填写了官方 URL 都不会改变上述隔离状态。

## 8. 人工审核、发布与重建索引清单

将任何待审核资料发布到正式知识库前，必须完成以下清单：

### 8.1 内容与权利审核

- [ ] 确认文件可读、编码正常，不包含不应入库的凭据、个人信息、商业秘密、生产密钥或恶意内容。
- [ ] 确认获得收集、存储、索引和展示所需的授权，并记录许可条款。
- [ ] 与原始来源逐项比对关键事实、数值、单位、条款、适用范围和例外情形。
- [ ] 判断当前获得的是官方全文、官方目录元数据、官方页面摘要还是内部整理稿，不得混淆。

### 8.2 来源和版本审核

- [ ] 核验来源 URL 的发布主体、可访问性和当前内容。
- [ ] 登记机构、版本/标准号/文号、发布日期、生效日期、最后复核日期和复核人。
- [ ] 核对是否存在更新版、修订、替代、废止、勘误或当地补充文件。
- [ ] 重新计算待发布文档 SHA-256，与待审核记录对比并说明任何内容变更。
- [ ] 只有完成独立复核后才能把 `official_claim` 转化为正式的官方来源登记。

### 8.3 发布和索引验证

- [ ] 由有权人员将已审核文档移入 `data/kb`；待审核 API 本身不执行这一步。
- [ ] 在 `data/source_registry.json` 中添加唯一来源记录，更新预期文档数量，并准确设置来源分级。
- [ ] 运行 `python scripts/build_index.py` 重建索引。
- [ ] 确认文档哈希和每个片段哈希已写入索引，且来源清单没有缺失或多余项。
- [ ] 运行全量测试，并对典型问题执行有命中、无命中拒答、官方来源过滤和高风险人工确认回归。
- [ ] 核对 `GET /api/knowledge/status` 的文档数、片段数、来源分级、索引哈希和构建时间。
- [ ] 保留审核人、发布人、发布时间、变更说明、测试结果和回退点。

## 9. 定期复核与下线

- 法规、标准、安全、海事、海关和环保资料应设置明确的下次复核日期，并在每次高风险应用前确认当前有效性。
- 定期检查来源 URL、发布机构、版本、哈希、许可条款和当地适用范围。
- 发现来源失效、内容不一致、新版替代、错误摘要或授权终止时，应立即降级或下线该资料，重建索引并评估已生成回答的影响。
- 复核与下线操作应留存审计记录，不得只覆盖原文件而不记录变更原因。

## 10. 可靠性边界

小懿AI无法保证收录“所有港航资料”，也无法承诺知识和数据“百分之百真实”。原因包括：法规和标准会修订，官方网页会更新，索引摘要可能缺失上下文，某一港口的现场制度和生产数据也必须由该港口授权后才能核验。

工程上应通过以下机制降低风险，而不是隐藏不确定性：

- 为每份资料和每个证据片段保留可追溯来源和 SHA-256；
- 记录发布机构、URL、版本、复核日期和授权范围；
- 区分内部整理、官方摘要、官方全文和现场授权数据；
- 证据不足、版本不明或来源过期时拒答；
- 对高风险结论保留人工复核和执行授权边界；
- 定期复核、重建索引、回归测试，并对过期来源降级或下线。

这些措施能够提高可审计性和可靠性，但不能取代监管机构、标准发布方、港口业务责任人和专业人员的最终判断。
