# 小懿 Harness V13：自主工具决策、跨系统操作与 RL 接口

日期：2026-11-01。验收证据位于 `.codex_artifacts/harness-v13-20261101/`。

## 本轮改变了什么

新增 `planning_mode=adaptive`：由现有本机 4B 模型逐轮选择工具、参数、追问或结束；不填写必需工具序列，不套用固定任务模板。原有 `contract` 模式、规则驱动、固定业务模板、联合演示和研究实验仍保留。两种模式在界面明确区分。自主模式没有模型时拒绝启动，不会悄悄改用规则。

Harness 不是另一个模型。它管理模型能看到的上下文、可调用工具、审批、预算、任务持久化、执行反馈和独立核验。模型决定下一步；Harness 校验权限、用户明确参数、实际回执与结束条件。明确数值约束可锁入动作 Schema，这属于输入约束，不是模型自行学会了参数理解。原有确定性流程与自主模式不能混称。

主聊天框开启“智能操作”时，可将跨系统操作请求交给同一持久化 Harness；概念问答继续走原有对话。任务卡支持具体操作审批、补充约束、暂停、继续、取消、刷新、恢复后核查、回执与 RL 研究轨迹导出。刷新页面保留任务编号，网络错误保留幂等请求编号。

统一启动脚本 `scripts/start_harness.py` 使用运行清单、统一数据库和代码指纹，区分磁盘代码与已加载代码。`启动小懿Harness.command`、已配置后的 `run.sh`、上海联动启动器使用这一入口。显式端口与 `XIAOYI_LEGACY_RUNTIME=1` 保留旧开发启动方式。模型服务和下游服务仍须可用；此启动器不会下载或替换模型。最终地址、进程和源码指纹以 `acceptance-summary.json` 的部署核验为准。

## 可调用的实际操作

| 系统 | 本轮自主模式可用的操作 |
|---|---|
| 港口数字孪生 | 读取状态、运行帧、能力覆盖；调用原有情景评估 |
| 能碳驾驶舱 | 读取状态、快照、情景目录、预测和决策记录；参数对比试算；暂停/运行模拟时钟并恢复 |
| 马六甲沙盘 | 读取状态、快照、决策记录；变更模拟情景、暂停/运行模拟时钟并恢复 |
| 航行模拟器 | 检查项目、引擎与隔离状态；调用已有 SAC 执行独立原生短时样本并核验回执 |
| 既有 RL 实验 | 读取已完成实验与基线比较；按已封存策略、数据、种子实际重新推理回放 |

联动动作从 8 项增加到 10 项；新增独立的读取、执行核验、恢复工具。动作仍仅限登记适配器，不是任意软件、任意 Shell 或真实生产设备控制。航行修复覆盖项目/引擎定位、独立无界面原生执行和请求哈希绑定回执；四秒样本不是完整航次，也不是桌面窗口操作验收。

## 核验与失败恢复

- 每个成功动作结束后，运行层自动调用独立核验工具，重新读取持久回执与当前配置。轨迹明确标识这一步由运行层触发，不把它计成模型自主选工具。核验失败的反馈交回模型处理。
- 恢复操作使用本任务原动作引用，检查当前配置，冲突时停止，不覆盖其他操作。
- 恢复未决时，原操作的成功回执不能证明恢复成功；必须看到恢复标记及当前配置一致。
- 只读失败允许有界重试，保留原失败与后续恢复引用；未知结果的写操作不自动重放。
- 参数不合法或遗漏用户明确数值时，在执行前反馈模型修正；重复无进展调用被阻止。
- 总结出现无证据数值时，向模型返回具体数值错误，最多纠正两次；不放宽数值门禁，也不重新执行已经成功的操作。
- 明确要求情景目录、能力覆盖或运行快照时，仅看到服务在线不能交付完成。
- 审批绑定具体参数和回执。验收脚本的模拟操作审批明确标注为“测试程序审批”，不是独立人工审批。
- 工具原始工件和事件链可核验；这是本机一致性检查，不是外部签名或第三方存证。

独立结束检查覆盖动作回执、恢复义务、明确数值和目标系统证据。它不能证明任意自然语言目标全部满足。多系统目录、条件分支和具体参数另有预先写定的验收检查。

## RL 结合方式与研究边界

当前实现两个接口：上层模型通过 Harness 调用下层既有 RL 策略；导出真实“观测引用—模型动作—工具反馈—结束核验”轨迹。导出带事件链和工件哈希检查，明确 `training_performed=false`、`reward_assigned=false`。本轮没有训练、微调或替换语言模型，也没有把这些开发案例当成独立测试集。

后续可把上层作为受约束的序贯决策问题：状态包含目标、观测、剩余预算、执行错误；动作包括选择工具、参数、重试、追问、恢复和结束；奖励由外部任务判定、恢复成功与成本给出。越权和虚假完成应作为硬约束或失败门禁，不能靠模型自评分覆盖。可先训练独立的轻量工具选择策略，再研究语言模型的多轮 RL。两者均可保留现有模型作为基线。

有说服力的实验需要比较固定流程、未训练自主 Harness、RL 训练后的自主策略，并使用未见任务、不同故障、不同状态分支及多种种子。指标包括真实任务完成率、错误操作率、核验覆盖、故障恢复率、调用成本和延迟。对比必须采用同一工具权限与预算。仿真中的效果不能直接外推到真实港口。

研究依据：[Agent Lightning v1.0](https://arxiv.org/abs/2608.17528) 明确讨论部署时 Harness 参与智能体 RL 训练；[AgentGym-RL](https://arxiv.org/abs/2509.08755) 研究多轮、长时程工具交互中的 RL。这支持“活跃研究方向”的判断，并不证明小懿已有论文中的能力或效果。

## 实测结果

机器可读完整结果及最终运行地址见 `.codex_artifacts/harness-v13-20261101/acceptance-summary.json`。所有实际模型失败轮次保留。空目录且无任务编号的轮次是启动失败，不能计入模型成功率；机制测试中的脚本驱动不计作模型自主能力。

已确认的适配器实测包括：能碳时钟暂停、观测、恢复及再次回读一致；航行已有 SAC 独立原生短时样本通过。实际模型案例、耗时、成功/失败以及页面验收另列于验收汇总，不能以适配器通过代替模型通过。

十项适配器已重新逐项实测，全部通过，包括相同请求幂等、每项三次观测、配置恢复与生产权限关闭。新证据为 `reports/linked_agent_acceptance_harness_v13_20261101.json`；旧证据保留。发布检查扩大到十项动作后通过。

真实 4B 能碳参数试算完整通过，三个指定数值准确，含自动回读核验和模型总结，墙钟约 306 秒。航行任务完整通过，执行既有 SAC 原生样本，墙钟约 584 秒，过程中有重复查询及一次重复操作提议被阻止。这些是本机有其他工作负载时的观测耗时，不是受控性能基准。

八份旧业务 RL 实验的 `rl_lab/algorithms.py` 指纹与当前代码不一致。`strategy.compare/replay` 保留原有拒绝条件，未将历史结果冒充当前兼容结果，也未改写指纹或自动重训。诊断见 `rl-compatibility-diagnostic.json`。因此，SAC 航行联动已实测，旧业务 RL 实验的当前版本回放仍待兼容复验。

马六甲曾出现健康与快照接口同时超时，随后自行恢复；没有重启或修改其源码，内存模拟进度保留。日志同期有大量临时导出目录热更新，可能与文件监听负载有关，但没有性能分析证明因果。原始现象与恢复读数见 `malacca-incident.json`。

开发中已暴露的问题包括：4B 重复状态查询、遗漏数值参数、空计划及 CPU 推理请求超时。相应增加了无进展阻止、参数约束、计划格式约束、可调用签名上下文和有界请求时间。保留这些失败证据，不宣称首次运行全通过。
