## 结论与评价口径

小懿的长处已经是任务执行闭环，而非只有问答：计划、工具、审批、持久化、恢复、跨系统业务执行、回读、补偿和客户端签收均有代码及历史验收材料。本轮没有把这些历史记录重新包装成今天的现场实测。当前短板主要在决策证据的深度：任务成功不能证明方案更优，多个种子不能自动证明统计可靠，漂亮孪生画面不能证明物理可信，公开总量不能代替逐船逐设备事件。

本轮增加了真实公开历史资料、时间一致的情景输入、JIT资源约束对照、点预测与区间验证，以及更严格的RL准入。本机功能验收与“达到未来顶级港口生产体系”是两个结论。这里将用户提出的“超级智能标准”转成下述可测试的工程目标；它不是某个已获得的认证或国际排名。

本轮**功能闭环**允许真实公开历史数据与显式工程参数组合进行仿真；**真实性**仍逐字段说明。缺少现场参数的地方可以检验接口、逻辑、约束与恢复能力，不能据此宣称已经验证对应港口的物理精度、真实业务收益或设备控制安全。

## 可操作入口与接口

打开小懿 → **双模式港航联合系统 → 国际港口公开数据·历史复盘与策略验证**：

1. “查看完整公开来源”可展开各份官方链接、时期、单位、缺测和摘要。
2. 选择洛杉矶或新加坡，运行基线、高峰月需求敏感性或泊位/岸桥故障假设。
3. 查看三种JIT排程的完整约束检查、等待、迟延和完工时间。没有完整可行方案时暂缓，不把部分任务排完当作成功。
4. “验证NOAA水位预测”运行真实历史留出检验，并展示持续值基线和区间口径。
5. 导出复盘证据；RL研究区可选择新的同期AIS+气象数据集，查看置信区间、压力结果和具体阻断项。

Harness任务工作台另有“公开港口历史复盘与未来能力评估”模板，实际调用三个登记工具并保存证据链。

新增接口：

- `GET /api/harness/assurance/public-data`
- `POST /api/harness/assurance/historical-study`
- `POST /api/harness/assurance/forecast-validation`
- `POST /api/harness/assurance/twin-validation`：外部提供的预测/观测对须符合时序合同，结果仍标明来源真实性需独立核验。
- `POST /api/harness/assurance/portcall-plan`：本地规范化合同，不冒充完整DCSA接口。

## 验收材料

机器可读回执及截图位于 `.codex_artifacts/future-port-20261030/`。最终结果见同目录 `ACCEPTANCE.md`。早期模型不必要追问与当时的失败摘要保留在 `http-acceptance/`，修正后的结果另外保存，不能删掉早期失败后只报告成功样本。

复跑：

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/run_future_port_acceptance.py --model --research --out .codex_artifacts/future-port-recheck-NEW
```
