# 小懿 Harness V12：自由摘要语义与快照时效

日期：2026-10-31（Asia/Kuala_Lumpur）。本轮只改 Harness 的证据供给、摘要检查、上下文和读取顺序；不更换4B权重，不修改预测、RL、MPC或年度孪生算法门槛。

原始记录：[harness-v12-20261031](../.codex_artifacts/harness-v12-20261031/)。原V11记录保持不变。

## 根因与反证

1. **模型没看到足够的语义事实。** 原 `runtime.snapshot` 摘要只选 energy、overview、fleet_summary、quality；完整工件有港区身份、告警、船舶ETA/ATB，但模型上下文不含这些必要实体字段。大量无关能耗参数反而占据上下文。摘要压缩还能继续截短字符串，缺少“哪些字段必须保留”的合同。
2. **旧检查只证明数字存在，不能证明它属于正确字段。** 新基线真实4B把港区编号写成“11”，把船舶数量当ETA、吞吐量当ATB、岸桥利用率当岸电负荷；原状态仍为completed。它们在本轮独立结果检查中均失败，不能计为成功。
3. **空值、已有信息和现场接入缺项混淆。** 模型把0值写成缺项，把检索答案要求补充真实港口身份套用到已有模拟港区身份上；后续实测还出现“生产控制权限关闭，所以无法读取数据”的无依据因果。
4. **无关说明和纠错轮次增加推理耗时。** 原模型每次都接收联合系统、历史研究等不相关说明，参数Schema又在提示中重复。遗漏资产编号、未注明模拟来源会导致额外整轮推理。记录每轮输入字符数、token与请求耗时后，可以区分工具耗时和模型耗时。
5. **快照采得太早。** 对独立通用SOP检索任务，原先先采集快照，再等待检索决策、检索和最终摘要。工具通常很快，但模型等待消耗了快照有效期。
6. **精简上下文仍须保留参数含义。** 第一轮真实API交接任务把指标查询选成 `dataset=port_calls`，并把闸口队列选成待靠船舶。结构合法不代表任务完成。已补回当前工具的指标含义；正式问数/交接模板增加明确要求指标的独立核验，实体表不能充当指标证据。
7. **工具动作中的无用正文很耗时。** 同一失败任务在每次工具调用中重复用户目标，一轮模型请求超过120秒；总耗时307.827秒，交付快照年龄284.30秒。已将本地工具动作无需展示的 `text` 固定为空，保留实际模型选参、工具回执及最终自由正文；风险工具的模型Schema最多120秒，最终独立时效门槛仍是120秒。
8. **情景数组在模型传输格式中失去边界。** R4真实交接虽选对指标，情景对比仍连续两次超时。单独保存输入并限量复现后，原始输出显示在`normal, energy_peak, storm`后反复生成`storm`，并以`finish_reason=length`结束。通用Schema精简删除了数组min/max长度，实际本地引擎又不支持`uniqueItems`。R5对本地`twin.compare`保留全部26种不重复的2—5情景集合，以有限枚举约束生成。只规范不影响计算的分支排列；工具仍以前置的快照情景作为基线。重复校验、独立推演、原120秒交付门槛均保留。
9. **参数合法仍可能漏做明确要求的情景。** R5消除了重复数组，5工具在124.080秒完成、快照年龄111.66秒，但只对比常态和大风，漏掉需量高峰，独立验收仍失败。R6把明确肯定式比较句中的已登记情景名称作为必要覆盖项，模型参数必须包含它们，最终再核对实际推演工件。否定、排除或运行中变更等复杂意图不做这个简单推断；仍保留原始约束交给模型，不能称为任意意图理解已验证。
10. **正常流程也缺少时效余量。** R6已完成全部指标与情景，但总耗时134.494秒、快照年龄121.35秒，仍判失败。各轮输入从1519字符增加到2769字符，最后一轮预填充约20.09秒。R7仅对无追加约束、未发生工具失败的固定业务中间阶段保留目标、技能、记忆/计划（若有）、必需工具和结果ID，省去摘要写作说明及此时无需阅读的工件摘要/哈希；模型仍逐步选择参数。宿主保留原始工件并强制执行预算、权限和所有核验，最终自由摘要、追问/补充约束、失败恢复沿用完整上下文。

同一Qwen3-4B Q4_K_M权重在改进运行层后能够通过新的指定任务，因此不能把这些问题简单归结为“4B体量不够”。本轮没有跨模型体量对照，不能证明所有语义限制都与模型规模无关。

## 修复方式

### 语义事实和核验

- 新增 `app/harness/semantic.py`。从原始工件生成有限的来源事实视图，保留字段路径、实体、标签、单位、实际值和状态。`present`包含0及false；`null`、`absent`、`empty`分别保留，不能补成0。
- 用户明确要求的字段与主要告警成为摘要必需项。告警需保留资产编号和异常内容，不能只写一个事件ID。
- 模型上下文单独保留必要事实，普通摘要压缩不删掉它们；若固定事实本身超预算则明确失败。用户追加约束后，从原始工件重新推导视图。
- 最终检查从工件独立读取事实，不信任模型自己声称“已经覆盖”。检查字段绑定、必要实体/告警、部分错误缺项声明、模拟来源及部分错误因果。仍采用最多两轮有反馈修正，失败则阻止发布。
- **正文仍由实际4B自由生成。** 这些修复没有把自由摘要替换成规则拼接报告；正式五工具交接继续明确标记为工件编译报告。

目前明确覆盖港区身份、观测时间、指定船舶ETA/ETB/ATB/ETC/ETD、岸电/电网需量/储能SOC，以及主要告警等检查。它不是任意自然语言、实体关系、因果和法规适用性的完整证明。

### 速度与采集时点

- 对已登记的本地读/算任务使用针对性提示，只保留当前工具所需约束。完整工具权限、参数Schema、必需工具、用户补充、预算及最终核验仍生效；开放或其他工作流沿用一般上下文。
- 固定业务模板的中间阶段只需要引用和下一步参数；原始业务事实由工具读取，最终自由摘要需要的事实仍保留。
- 独立通用资料检索先做，快照后采。明确要求“先读快照再检索”或检索依赖快照的任务保留原顺序。
- 增加 `model.performance` 事件：记录上下文档位、输入字符数、prompt/completion token和真实请求耗时；兼容引擎返回的推理计时。
- 不再让本地模型给每个工具动作重复撰写目标说明；最终回答照常生成。当前工具的必要参数含义保留，避免精简提示导致错误选参。

**未放宽：120秒时效、未来时间容差5秒、原始时间戳、必需工具、完整性校验、预算和生产权限。** 没有把旧快照重新盖上当前时间，也没有偷偷改用规则驱动。有效期不足仍暂缓。

## 分阶段实际验证

每阶段在实测前保存协议并冻结实现，然后采集新的数据。失败记录不覆盖：`protocol.json`及`protocol-r2.json`至`protocol-r7.json`。R4协议在补丁编写后、新模型实测前保存；未观察新样本结果再设门槛。R5—R7修改情景工具约束和固定业务中间上下文，自由摘要路径保留R4四项隔离证据及R5新真实API摘要证据，R7再用新目标、新快照验证受影响的交接流程。

隔离测试使用新生成并明确注入字段的工程模拟数据，不是新取得的真实港口生产数据，也不是第三方盲测。初期诊断夹具保留了原模拟器部分元数据镜像；最终夹具修正了港区编号镜像、适配器标识、原始payload哈希，并移除注入前的旧动作建议。历史文件保留；最终验收以修正后的新数据与真实API任务为准。

独立脚本按预登记预期检查模型正文，不把运行层自己的 `passed` 当作唯一依据。新任务的名称、编号、字段内容与观测时间均不复用先前回执。期间没有重新训练4B。

## 评分原则与限制

按原V10五维百分制复评，不把门槛换低再加分。对已覆盖的语义约束，可依据新的本地集成实测更新专项证据成熟度；少量任务不作为开放世界准确率。

| 评分口径 | 原分 | 本轮 |
| --- | ---: | ---: |
| 自由摘要语义证据成熟度（5分制） | 2 | **3**：有限字段/告警核验与真实本地集成通过 |
| 交付核验、港航交接证据成熟度（5分制） | 各3 | 各3：新增时效/覆盖证据，尚未跨入真实站点影子运行 |
| 原综合Harness评分（100分制） | 75 | **75**：跨场景和生产成熟度门槛未改变 |

机器可读评分另存于[data/evaluation/xiaoyi_harness_scorecard_v12_20261031.json](../data/evaluation/xiaoyi_harness_scorecard_v12_20261031.json)，不覆盖V11或V10历史评分。这些分数表示证据成熟度或既有粗评，不是模型准确率、国际排名或生产资格。

CPU推理仍是实际限制；减少无关上下文和采集等待不能保证任意长任务、并发排队或更复杂需求都在120秒内完成。超时仍需暂停或交付明确限定的历史分析。真实港口接入、长期稳定性、分布式恢复、外部盲评尚未由本轮补齐。预测70、RL相对强MPC收益30、年度孪生50的原评分不变。
