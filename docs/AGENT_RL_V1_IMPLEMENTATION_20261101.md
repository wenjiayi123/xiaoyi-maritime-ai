# 小懿多任务语言模型 RL · 本机实验实施记录

日期：2026-11-01。状态：实施中，尚未验收，尚无本轮训练效果结论。

## 已确认范围

用户选择本机现有 1.7B 语言模型开展实际训练，后续再迁移 4B。保留原 4B、既有 LoRA、业务 RL 策略及数据。新实验不能把业务控制 RL、固定 Harness 流程、外部模型代做，记为语言模型 RL 的效果。

原讨论的 60 项能力是长期目标目录。首轮实验围绕现有系统建立多个可核验任务族；验收任务需要而现有系统缺少的功能按需补齐。未接入或未训练的能力不标为完成。

## 执行步骤

1. 固定验收任务、资源检查、保留原模型及代码基线。
2. 建立统一工具契约、可复位任务环境及独立结果检查；补齐必要接口。
3. 构造多任务及正常、参数错误、读取失败、执行结果不明等分支。
4. 冻结训练、验证、独立测试分区；测试不得用于选模型和修改奖励。
5. 运行固定流程与原始语言模型两组基线。
6. 使用训练分区做 SFT，记录实际参数更新和检查点。
7. 从同一 SFT 检查点进行 RL，依据环境执行结果更新语言模型适配参数。
8. 使用相同工具、预算、环境及评测口径，评价四组与原能力保持。
9. 接入小懿的可见操作入口，执行预先约定的真实系统验收任务。
10. 生成实测对比图、原始记录、训练说明、失败案例及专家展示页。

## 首条端到端验收指令

“读取港口、能碳和马六甲系统的当前状态；比较基准绿色偏好 0.50、候选绿色偏好 0.82、碳价 85 元/吨的能碳方案；评估港口高密度靠泊情景。遇到可恢复的读取故障请处理后继续，最后给我带来源、参数、结果和实际执行记录的联合报告。只在本机工程模拟中操作。”

成功要求：实际系统返回有效响应；两个能碳方案同数据源、明确采用指定参数；港口评估具有实际计算结果；相关结果独立核验；报告链接到原始证据；错误与恢复记录保留；无虚假完成。该任务预先登记为开发验收案例，不计入独立测试分数。

## 四组对照

- A：明确记录的固定流程/规则策略。
- B：原始 1.7B 语言模型 + 相同 Harness。
- C：同底座 SFT 模型 + 相同 Harness。
- D：从 C 继续进行 RL 的模型 + 相同 Harness。

RL 的增量主要由 D 对 C 判断，D 对 B 表示整体训练效果。不能将 A 故意削弱、把失败删掉或用不同权限/预算。若只有单次小规模试验，标为探索性实验，不宣称统计显著或普遍优于工程流程。

## 证据与展示原则

记录模型身份、原始权重/适配器摘要、训练配置、训练数据摘要、随机种子、每次模型决策与工具结果、奖励来源、失败和实际耗时。奖励不能来自模型自我声称完成。工具输出和 Harness 自动步骤不作为模型生成动作计分。

对比图只从实际评测 JSON 生成。未运行项为空且明确标注，禁止填入示意提升率。检查任务完成率、参数正确性、恢复率、调用成本、原能力保持和各任务类别表现。

## 当前资源

Intel i9、16GB 内存；已有本机 Qwen3-1.7B 完整权重、PyTorch 2.2.2、Transformers 4.51.3、PEFT 0.15.2。默认 4B 为 GGUF 推理版本。历史 1.7B 64 步短上下文 LoRA 记录约 587 秒，仅作为本轮资源探针参考，不能当成本轮训练结果。

## 实施进展

- 已完成资源探针：真实前向、反向与适配参数改变；仅证明可训练，不计为任务效果。
- 已建立 8 类、13 个登记动作候选的可复位环境，覆盖工具选择、参数候选、多步协作与故障恢复；其余长期目标不计为已训练。
- 训练/验证/测试分别为 48/16/24 个案例；初始输入跨分区无交叉，测试集 24 个输入各不相同。任务族已知，留出参数组合；不宣称未知业务类型泛化。
- 首个 80 步 SFT 试验在验证中反复读取，已保存并停止，未访问独立测试结果。
- 第二个试验改善状态表述并完成 240 步 SFT。检查点保留，第三个运行从同一检查点继续 RL，不重复声称新增 SFT。
- 为本机加入冻结前缀激活复用；训练过的检查点上，核对前向 logits 和适配参数梯度，最大绝对误差均为 0。只减少重复计算，未替换语言模型为另一个策略网络。
- 原系统适配器探针已完成：三个系统读取、能碳双方案比较、港口情景、证据核验与报告；此探针由规则驱动，明确不计为模型验收。
- 工程回归已通过 1030 项 Python 测试和 47 项前端测试（见本轮日志）；后续改动另做针对性验证。
- 最终四组指标须由原始轨迹独立重放核对后绘图。故障恢复率以全部分配故障案例为分母，未尝试参数时显示无数据，避免不同组分母不一致。
