后续港航业务补强与最新回归见 [港航业务评审及补强记录](HARNESS_MARITIME_REVIEW_20261029.md)。

2026-10-31 的实际 UI 演示、4B 失败样本、修复、重新验收与展示边界见 [Harness V11 检查与演示记录](XIAOYI_HARNESS_REVIEW_V11_20261031.md)。旧日期中的耗时和成绩只代表当次运行。

随后完成的自由摘要字段语义与时效补强见 [Harness V12 根因、修复和新任务实测](XIAOYI_HARNESS_V12_20261031.md)。当前自由摘要保留来源事实视图，进行有限字段/告警语义检查，并记录每次模型请求的性能信息；不将这些检查称为完整语义证明。

## 港航业务任务

工作台的“业务任务”可选港区结构化问数、同基线孪生情景对比、港航联合研判与交接等。选择后点击“开始任务”。2026-10-31 本机管理员目录实际返回24个登记工具，具体可用项随角色与任务合同收窄；其中4个港航业务工具如下。

| 工具 | 功能 |
| --- | --- |
| `maritime.query` | 查询当前任务快照上的12个语义指标和6个实体数据集；保留单位、字段与来源；支持精确实体标识和截取披露 |
| `maritime.risk` | 检查数据时效、质量、功率平衡与工程风险，列明规则、阈值和待核验事项 |
| `twin.compare` | 同种子、时钟、序号、执行状态、模型与校准数据的独立情景采样；先检查基线可复现，不修改当前模拟器 |
| `maritime.handover` | 仅汇总同基线的问数、风险及对比，生成待人工接收的交接草稿；交付时再次检查时效 |

创建任务可传 `template_id`：`port-query`、`twin-study` 或 `port-briefing`。工具参数 `source_ref` 必须是当前任务成功 `runtime.snapshot` 的结果编号，例如 `T1`。`maritime.handover.result_refs` 必须同时包含问数、风险和对比的成功结果编号。依赖工具不能省略或越权扩展。

未显式设置时，模板的活动时间/token预算分别为：问数300秒/16000、情景对比420秒/24000、联合研判600秒/32000。显式传入的预算优先，运行中显示生效值；幂等校验包含生效预算，不能用同一请求编号偷偷改变预算。

指标目录与模板通过 `GET /api/harness/capabilities` 的 `maritime` 字段返回。问数提供功率kW等明确单位，不提供任意SQL。实体数据集为挂靠、泊位、设备、堆场、闸口和告警。空值不当成零。

情景采样窗口1至60分钟、2至12个采样点，2至5个登记情景；原基线情景会保留为参照。它没有统计置信区间、最优策略或经过现场验证的预测准确率。设备SOC仍是工程示例，不用于续航预测。

根时间与组件观测时间默认最多120秒；未来超过5秒、缺少时区、功率平衡异常等会抑制建议。可分析不代表放行现场作业，`operational_release` 固定为false。交接状态为 `draft_requires_human_acceptance`，人员、期限与签收不会由模型捏造。

时效结果记录 `assessed_at`，工作台显示“检查时”的年龄与结论，不能将历史回执当成当前数据仍然新鲜的证明。

最终回答发布前还会重新检查原快照，结果位于 `final.verification.delivery_readiness`。证据已过期时，摘要必须说明暂缓，最终通知也会注明按已采集快照使用。部分未经支持的显著性、最优性和全部合格声明会触发最多两次有反馈修正；仍不合格则阻止发布。这不替代完整语义验证和人员复核。

该检查同样覆盖仅使用 `runtime.snapshot` 的自定义任务，不能因没选业务模板而跳过。原始快照有未关闭告警时，肯定式“均正常／没有风险”会被阻止；明确说明“不能声称均正常”不作为放行声明。120秒时效门槛不因本机模型速度慢而放宽。

新增复现命令：

```bash
.venv/bin/python scripts/run_harness_maritime_acceptance.py --driver rules --output /tmp/maritime-rules.json
.venv/bin/python scripts/run_harness_maritime_acceptance.py --driver model --output /tmp/maritime-model.json
.venv/bin/python scripts/run_harness_maritime_acceptance.py --driver model --template port-briefing --default-budget --output /tmp/maritime-briefing-model.json
```

规则模式验证三个模板；模型验收脚本默认实际运行结构化问数，指定模板可检查完整工具流程。联合研判交接采用 `output_policy=verified_business_report`：模型负责工具决策，正式报告由五个成功工具的工件编译并核验，不请求模型重写事实。`final.synthesis` 标明来源、工件名及 `model_authored=false`。它不作为模型自由摘要能力的证据；普通模型任务继续使用原生成方式。运行中追加用户要求会关闭自动交付，保留新约束的优先级。

2026-10-29 的本机实际记录为：6次模型决策、5次工具调用，124.382秒完成正式交接报告。当前4B模型的复杂自由摘要曾被业务检查阻止，详见评审记录；不要把这个工件交付成绩描述成自由生成摘要的准确率。

## 启动与使用

使用原来的 `bash run.sh`。有已登记的本地权重时，启动脚本沿用原有模型栈，并将默认上下文设为8192；显式设置的 `XIAOYI_LOCAL_MODEL_CONTEXT` 优先。没有模型时，可以使用明确标识的规则驱动模式。

1. 打开任务工作台，输入目标，选择自动、模型或规则运行。
2. 设置步骤和执行时间预算。默认不读取偏好记忆。
3. 查看计划、实际工具结果、步骤/工具/token/时间使用情况。工具结果可查看完整原始工件。
4. 信息不足时回答追问；执行中可补充约束，尚未执行的旧模型决策会失效。
5. 联动操作先生成具体方案。审阅动作、参数、有效期和摘要后，批准或拒绝。
6. 暂停在当前I/O完成后的安全边界生效；继续会检查当前角色权限。取消不代表已经发出的目标请求被撤销。
7. 从历史任务恢复视图或导出完整JSON回执。关闭面板不取消后端任务。

示例：

- `计算 (120+80)/4`
- `检索岸电接入前的核验事项，保留来源，不调整设备。`
- `读取当前港区运行快照，再检索岸电SOP，说明数据模式和缺失信息，不调整设备。`
- `马六甲切换集中到港并观测`（先启动登记的马六甲模拟器；会请求具体方案审批，默认恢复配置）

## 模型与规则

任务运行层使用独立的下一步决策接口，不改变原问答增强链路。默认复用舷鸥模型设置，也可通过以下变量覆盖：

```bash
XIAOYI_HARNESS_MODEL_BASE_URL=http://127.0.0.1:11435/v1
XIAOYI_HARNESS_MODEL_NAME=已配置的模型别名
XIAOYI_HARNESS_MODEL_API_KEY=由部署者配置
```

接口需支持 `/chat/completions` 和 JSON Schema 结构化输出。已实际验证本项目登记的 Qwen3-4B Q4_K_M 与本地 llama-server；其他兼容服务必须单独验证。当前适配器不宣称覆盖所有厂商的原生工具调用、流式协议或SDK。

本机轻量模型采用精简交付档：提示目标为180字以内，结构化传输上限为400字符。命中字符上限或服务返回 `finish_reason=length` 不视为正常交付，计入实际token并进入有界修正。详细结果完整保存在工具工件中。工具名与参数使用绑定Schema，阶段结束后不再扩展无关工具。其他模型档仍需独立进行质量与时延验证。

远程模型必须使用HTTPS、配置密钥，并显式允许 `XIAOYI_MODEL_EXTERNAL_DATA_ALLOWED=true`。默认不向远程发送任务资料；运行模拟和联动证据沿用原问答链路的本机处理边界，即使启用一般外发许可也不发送至远程模型。密钥不进入任务状态、工具上下文或回执。模型模式出错不会静默替换成规则模式。

规则模式使用明确的规则、登记工具和既有知识引擎，结果标识“未使用模型自主规划”。它用于无模型运行和确定性机制验收，不能作为模型智能水平的证据。

## 任务合同与预算

创建任务可设置 `allowed_tools` 和 `required_tools`。必需工具必须是允许工具的子集；未显式给出时，仅对快照、检索/SOP和明确计算等关键词建立保守的完成条件。

有明确必需工具的任务采用有界证据流程：按依赖和用户明确顺序获取证据，合同满足后进入交付阶段。独立通用SOP检索可先进行，再采集有120秒时效门槛的快照；明确要求“先快照再检索”或检索依赖快照时保留该顺序。需要自主追加工具的开放式研究，可显式设置 `required_tools=[]`；工具权限与预算仍然强制生效。运行中新增用户要求会重新开放决策范围。

如果当前合同要求 `runtime.snapshot`，且尚无读取失败，先完成可直接取得的必需读取，再决定是否有必要追问；不会向用户索要本机工具本来可取得的信息。失败后仍可追问；这不新增工具权限。

模型不能仅凭流畅回答宣布完成。交付前检查必需工具是否成功执行、引用编号、原始工件摘要、数值是否在引用结果中出现，以及生产权限表述。缺少必需工具时，最多进行两次补全反馈，并受总预算约束。已完成的必需读取会暂时从候选中移开，帮助模型继续处理缺失项。

对于模型自由快照摘要，还从原始工件检查已登记的必需字段、主要告警、部分错误缺项声明、0与空值及模拟来源。`final.verification.semantic_check`列出覆盖路径和有限适用范围。`source_facts`保留字段路径/实体/值/单位/状态，普通摘要压缩不得删除它；固定约束超预算时明确失败。现场接入缺项不等于模拟港区身份缺失，生产控制权限关闭也不意味着无法读取数据。

正式问数/交接模板对目标中明确要求的电网需量、岸电负荷、低电量AGV、闸口队列核对实际指标行。查询实体表成功不能代替完成这些指标问数。模型风险参数最多120秒，最终交付继续按原始快照的120秒门槛独立核验。

默认最多12次模型/规则决策、16次工具调用、180秒累计活动时间、16000 token、18000字符模型上下文。并行研究的每个子调用均计入工具预算。等待人工输入、审批或暂停期间不消耗活动时间。预算退出不标为任务成功。

token使用来自服务返回；服务未返回时标为估算。模型调用前有保守的上下文预算检查。当前预算不是财务计费结算；已经发送的有界I/O可能在预算到期后才返回，必须完成结果核对。

## 工具与执行环境

| 工具 | 作用与边界 |
| --- | --- |
| `knowledge.search` | 调用现有港航证据引擎，保留来源、质量和适用范围 |
| `runtime.snapshot` | 读取舷鸥原生模拟快照，原始对象完整保存到工件 |
| `linked.observe` | 读取登记的本机目标，不自动启动服务 |
| `linked.action` | 复用原有方案、审批后执行、观测、恢复及回执；操作权限继续检查 |
| `calculate` | AST白名单实数运算，限制节点与幂；没有任意代码执行 |
| `artifact.write/read` | 当前任务虚拟工作区，限制名称和大小；不能覆盖保留的工具结果或系统回执 |
| `skill.read` | 按需加载登记的版本化技能 |
| `research.parallel` | 最多3个只读/纯计算分支；逐项记录结果，子权限独立校验 |

虚拟工件存于SQLite，不提供任意主机文件访问。没有开放Shell、主机Python执行、真实设备控制或生产调度。并行研究分支属于受控工具并行，不宣称已经实现通用自主多智能体。

## 状态、恢复与未决操作

状态包括排队、执行、等待输入、等待审批、暂停、完成、部分完成、失败、取消、预算退出、阻止与待核查。

SQLite事务保存任务、工具意图、事件与检查点。任务执行有90秒租约，每10秒续期。过期只读工作转为可继续的暂停；存在未决副作用时转为待核查，不能直接续执行。恢复扫描发生在运行层启用后，通常在租约到期后完成。

“读取关联回执核查”只读持久化的原联动回执。只有该回执证明安全结束，才解除未决状态；它不会用重新执行操作来探测结果。被成功核查的原失败记录保留，并指向后续核验记录。目标回执本身仍不确定时，需要在原系统核查。

原有联动的目标互斥仍以单进程为边界。Harness自己的任务租约不能替代目标系统的分布式幂等、原子版本比较与设备联锁。多进程写操作和多机器部署需要额外验收，当前不承诺分布式恰好执行一次。

## 上下文、技能和记忆

原始目标、全部用户补充约束和计划保留在上下文中；大工具输出保存在完整工件中，模型接收摘要与引用。超出预算时先整理工具摘要，固定约束自身过大则明确失败，不静默丢弃用户要求。

固定业务模板且没有新增用户约束时，中间阶段只向模型提供足够选择下一工具的结果索引和短摘要，工具自身通过工件读取完整数据。联合研判最终阶段主要读取编译后的交接摘要，并保留尾部未决事项。用户追加要求后恢复一般上下文策略；这不删除原始证据。该调整用于避免本机CPU模型反复处理长JSON而超时，不用于证明语义正确性。

已登记本地读/算任务可使用 `focused_native_v12` 上下文，只保留相关工具说明；其他工作流沿用一般提示。`model.performance`事件记录上下文档位、输入字符、prompt/completion token和请求耗时，帮助区分工具慢、上下文大和生成慢。时效核验仍使用原始观测时间，不刷新旧快照的时间戳。

本地模型的中间工具动作 `text` 固定为空，避免重复生成不参与执行的目标说明；工具选择、参数与回执照常保留，最终自由摘要仍由模型生成。精简提示保留当前工具的参数含义，不以省略字段核验换取速度。

本地`twin.compare`传输约束枚举全部26种不重复的2—5情景集合，防止模型无限重复某个情景。计算仍使用原始快照基线，原本可选情景集合未减少；其他业务参数仍由模型在原合同内选择。重复情景的工具端校验继续生效。

未追加约束的任务，若肯定式比较句明确点名已登记情景，传输参数必须包含这些情景，最终核验再检查实际推演分支。否定、排除和运行中变更的复杂意图不由这一有限词汇规则推断；用户约束仍保留在模型上下文。这不等于任意自然语言任务覆盖已验证。

固定本地业务模板的中间阶段，在无追加约束、无失败时可使用`closed_tool_parameters`上下文：保留目标、技能、已有记忆/计划、必需工具和结果ID，模型只选择当前工具参数。原始工件、预算、权限和最终核验仍由宿主强制执行。最终自由摘要、追加约束或失败恢复使用完整上下文；`model.performance.context_stage`明确区分这两类调用。

任务选用技能时冻结其版本摘要和内容。新增技能读取带版本与摘要。偏好记忆按用户隔离，只有用户在工作台明确保存后才存在，最多30条；每个任务可选择是否读取，用户可删除。模型没有自动写长期记忆的工具。

## HTTP接口

全部接口继承现有身份和中间件；生产部署需沿用JWT配置。任务记录和工件受所有者/管理员访问检查。操作工具和审批另行检查操作权限。

审批事件保存实际审批人、角色、审批ID与动作摘要；控制和输入事件保存提交者。管理员代他人审批、续跑或输入时，任务保留原所有者的执行角色，不借用管理员权限继续执行。

| 接口 | 用途 |
| --- | --- |
| `GET /api/harness/capabilities` | 当前身份的工具、技能、模型与运行能力 |
| `POST /api/harness/tasks` | 幂等创建任务，`request_id`绑定请求内容 |
| `GET /api/harness/tasks`、`/tasks/{id}` | 历史与当前状态 |
| `POST /tasks/{id}/control/pause\|resume\|cancel` | 生命周期控制，前缀均为 `/api/harness` |
| `POST /tasks/{id}/inputs` | 幂等补充信息/运行中约束 |
| `POST /tasks/{id}/approval` | 审批具体动作，绑定ID、摘要和有效期 |
| `POST /tasks/{id}/reconcile` | 读取关联回执核查未决操作 |
| `GET /tasks/{id}/events?after=N` | 增量事件与游标 |
| `GET /tasks/{id}/stream` | 认证SSE，支持事件游标重连 |
| `GET /tasks/{id}/artifacts[/名称]` | 工件目录和完整原文 |
| `GET /tasks/{id}/export` | 状态、事件和工件回执及一致性校验 |
| `GET/POST /memory`、`DELETE /memory/{id}` | 当前用户显式记忆 |
| `POST /evaluation` | 隔离的确定性基础任务评测 |
| `POST /mcp` | MCP只读工具服务 |

任务SSE是应用自己的事件流。它与MCP协议的请求流、协议版本和重连语义分别实现，不混为一种协议。

## MCP

`/api/harness/mcp` 提供只读工具列表与调用，沿用HTTP身份，校验Origin。支持2025-06-18/2025-11-25的初始化与JSON-RPC工具接口，以及2026-07-28的请求元数据头校验。现代请求需要 `Mcp-Protocol-Version`、`Mcp-Method`、工具调用的 `Mcp-Name`，且与正文元数据一致。

这是受限的MCP服务端能力，当前不包含任意远程MCP客户端发现、OAuth授权服务器、采样、资源订阅或远程代码执行。具体第三方客户端仍需互操作验收。

## 可复现检查

```bash
.venv/bin/python -m pytest -q
node --test tests/*.test.js
.venv/bin/python scripts/run_harness_acceptance.py \
  --base-url http://127.0.0.1:8010 --driver rules --output reports/harness-rules.json
.venv/bin/python scripts/run_harness_acceptance.py \
  --base-url http://127.0.0.1:8010 --driver model --output reports/harness-model.json
```

`scripts/harness_browser_acceptance.cjs` 使用Playwright和已安装的Chrome检查真实工作台。需要对应Node包环境。

`scripts/run_harness_linked_acceptance.py` 是显式的模拟写操作验收，会临时切换马六甲情景并恢复；运行前确认登记服务与 `--target-url` 为同一隔离模拟器。不要把该脚本用于未经验证的生产目标。

## 质量边界

完整执行轨迹支持故障定位，不能替代独立评测。数值存在性不证明单位、因果与语义都正确；工具返回也不等于事实可信。事件摘要链用于本地一致性，不等同外部签名或防篡改存证。任务历史可能包含业务资料，部署者需配置适当的磁盘、访问、备份和保留策略。

目前对标的是公开主流运行能力的设计和可复现工程行为；国际性能排名需要更多模型、相同任务与预算、重复试验、独立评分和生产负载证据。
