## 使用入口

打开 `http://127.0.0.1:8010/`，进入左侧 **双模式港航联合系统**。小屏先点击顶部“打开功能侧栏”。原有对话、决策、数据、训练、知识库、任务及四系统联动入口继续保留。

- **企业受控模式**：填写目标、选择工程情景，生成待审计划；也可选择现有模型辅助理解和调用规划工具。审批绑定计划摘要、参数与五分钟有效期。实际步骤完成后，由Flutter端读取同一任务并签收，网页才显示全部完成。
- **RL策略研究模式**：显式创建小型业务策略实验，或选择已有当前版本实验；核对比较结果、曲线、模型和数据指纹，并可重新推理回放。研究联合计划固定实验和报告摘要。较差或不兼容策略不会自动进入企业模式。
- **停止**：任务停止、模型规划停止和研究停止分别提供，不依赖模型生成一段“同意停止”的文字。已执行动作保留真实状态；停止在有界调用或当前仿真边界生效。

这两个模式共用身份、任务、结果校验、预算和审计。模式不是两个独立的大模型。

## 六系统实际分工

| 系统 | 当前联合流程实际调用 | 输出与限制 |
| --- | --- | --- |
| 小懿 | 固定能力目录、模型工具选择、依赖计划、审批、执行、研究和汇总 | 可核对任务、事件链、工件和状态；本地哈希一致性不等于第三方数字签名 |
| 马六甲沙盘 | 读取实际模拟快照；获批时调整工程情景；完成或异常后检查并恢复配置 | 保存写入意图、变更前后快照和回写；配置恢复不倒放模拟时间 |
| 航行模拟器 | 独立Godot实例，正常准入接口加载现有开放水域SAC，运行240个物理帧并读取实际推理与运动 | 约4秒仿真样本、位置、动作、推理次数、移动距离、碰撞和最小间隙；不是完整航次或真实海峡交通复现 |
| 港口数字孪生 | 按显式情景映射调用运行序列评估，核对有限kW数据和模拟权限 | 交通延误来自沙盘聚合代理，不能冒充航行模拟器测得的到港延误 |
| 能碳驾驶舱 | 使用港区峰值映射试算偏好，实际调用基线及候选两次recompute并核对采用参数、数据哈希 | 更新驾驶舱演示试算参数及联动回执；不是下发设备控制或完成现场供电可行性证明 |
| Flutter端 | 提交、读计划、审批、停止、轮询、查看原始结果和签收 | 使用同一后端任务号与认证身份；签收记录证明客户端收到结果，不证明物理设备执行 |

现有单系统联动动作及原系统岗位审批路径保留。新的联合模板是 `federated_joint_assessment.v1`。目前没有将能碳全部岗位审批、设备模拟执行与回滚、所有沙盘决策或所有航行场景都改造成统一自然语言自动任务。未登记动作不属于已通过验收的能力。

各系统保留原地点、数据时间、模拟时钟和来源。联合流程使用联邦工程情景敏感性映射，尚不是同一个真实港口、同一实时事件时钟下的联合最优调度器。

## 策略研究与可信性修正

原能量、港口作业环境的趋势特征读取了下一条真实记录。本次改为当前减上一条记录，并升级为 `xiaoyi-energy-env.v3-causal`、`xiaoyi-port-operations-env.v2-causal`。测试通过修改未来记录验证当前观测不受影响。历史实验可查看；缺少当前环境、数据字段映射、代码或模型指纹的报告，不能作为当前执行证据。

当前固定实验采用Q-learning与Double Q-learning，五个种子29101–29105，每种每种子160回合，窗口24步；SOP、PID作为不训练基线。按时间70/15/15划分，参数校准只用训练段，选型只用验证段；测试段不参与训练或调参。每个策略独立环境实例，共用相同外生条件、约束、窗口及种子。保存全部曲线、失败候选、逐策略指标、模型和真实State/Action/Reward回放。

本轮NOAA港口代理环境由PID领先，UCI能源代理环境由SOP领先。两种RL都未超过最好基线，因此不自动晋级。标准差只是跨训练种子的离散程度；固定基线重复得到同一结果时标准差为零，不意味着真实业务没有不确定性。本轮没有获得可宣传的RL现场收益或统计显著性。

研究只训练受预算约束的小型表格策略，单个训练进程串行执行，独立存入 `.runtime/harness-research`。源数据、字段映射、港口profile、环境、执行代码、模型和报告均记录摘要。研究代码变动后，旧报告自动转为历史资料；已有工件不被覆盖。

## 执行与故障处理

- 计划先保存、后审批；审批检查身份、参数、摘要、执行源码和有效期。模型不能改写用户固定的目标、模式、情景和变更范围。
- 步骤按依赖推进，只把真实下游回执标为已完成；失败停止后续步骤。
- 同一请求编号绑定参数，重复提交不生成第二次操作；同一用户未结束联合任务有数量上限。
- 写入前持久记录意图。回执未知时进入待核查，提供只读核查，禁止自动重放或未经核对覆盖其他人的修改。
- 联合执行和研究分别使用操作系统文件锁，跨进程原子互斥。其他进程启动不会把活跃任务误判为重启；进程退出后锁自动释放。孤儿任务转为待核查或中断，不自动重复执行、训练。
- 暂停、继续、停止、预算耗尽、拒绝、部分完成、待移动端、未知执行和补偿失败分别显示。没有移动端签收不会显示六系统全完成。
- 极端天气尚无匹配的已准入航行样本，流程会明确停止；不会用平静水域样本冒充恶劣天气验证。

## 重现与启动

在小懿根目录运行：

```bash
.venv/bin/python scripts/run_joint_demo.py
```

它复用现有小懿服务；未启动时调用原 `run.sh`。Flutter端使用已经构建的 `dt_mobile_app/build/web`，只绑定本机7357端口。三个网页下游服务由获批联合任务按登记启动器启动。Godot样本使用登记的官方Godot路径。重复启动遇到错误服务占用端口会拒绝覆盖。

更新Flutter代码后，在移动端目录运行：

```bash
flutter build web --release --dart-define=API_BASE_URL=http://127.0.0.1:8000 --dart-define=XIAOYI_API_BASE_URL=http://127.0.0.1:8010
```

只读启动检查：`.venv/bin/python scripts/run_joint_demo.py --check`。候选模型可在联合面板“查看开源模型”内按需启动。缺少权重时使用 `scripts/download_harness_models.py --help` 查看固定版本下载方式；候选不自动替换默认模型。

关闭扩展：启动前设置 `XIAOYI_DUAL_HARNESS_ENABLED=false`。原问答和原Harness企业任务路径仍可使用。运行中任务先停止并处理待核查项，再停服务和回退代码；不要直接覆盖活动SQLite数据库或删除失败记录。

本机为Intel macOS，业务实验不依赖新装Torch。文件锁当前实现依赖POSIX，未验收Windows部署。原生Godot实际仿真已执行；桌面原生窗口自动化服务不可用，因此不把原生GUI全部按钮称为逐个点击验收通过。

## 面试展示建议

先演示一条企业任务：指令→模型工具选择或可靠模板→带摘要的计划→审批→五系统真实输出→Flutter签收。再展示同一环境中RL未超过PID/SOP的结果、来源与回放。最后选择未支持的天气，说明系统为何停止、哪些步骤没有执行。

可准确表述：**我实现了共用执行底座、双模式研究与受控联合评估，优先复用开源及既有模型，并用真实回执、版本隔离和故障测试约束执行。** 当前证据不足以称为世界顶级、港口生产可用或能自主完成所有港航任务的超级智能。
