# 小懿真实港口系统连接器接入手册

## 1. 当前交付边界

当前代码提供的是港口系统连接器的接口契约、安全配置、连接状态、健康检查、字段映射模板和写操作预检框架。它**尚未接入任何港口、码头、监管机构或第三方的真实生产端点**，也没有内置任何真实账号、密钥或证书。

必须区分以下三件事：

1. 连接器已出现在目录中，只代表系统具备该类接口的接入位置。
2. 健康检查成功，只代表已配置的健康端点实际返回成功，不代表所有业务数据完整、准确或及时。
3. 写预检通过，只代表安全条件满足；当前预检接口明确返回 `dispatch_performed: false`，不会下发生产指令。

未经港口方书面授权、接口规范确认、网络开通、凭据签发、字段对账、联调验收和生产变更审批，不得将连接器切换为 `live`，更不得启用写权限。

### 1.1 无现场端点时的完整闭环

默认页面不再用空白卡片代替港口数据，而是接入内置 `PortRealtimeSimulator`：它按 [`port-realtime.v1`](../data/contracts/port_realtime_telemetry_v1.json) 每 2 秒输出 10 个业务域和 153 个规范字段，并固定显示“公开数据校准实时模拟 / SIM”。五种因果场景、质量门禁、双人审批、模拟执行、审计和回滚都可在浏览器验收。

模拟器是连接器联调夹具，不是第九个生产连接器。公共 AIS 只校准交通包络，其他港口量级和影响是工程模拟；`physical_dispatch_performed=false`、`production_authority=false`。现场接入时连接器只需输出同一契约，页面和业务链不用重写，但必须重新完成现场准入，不能沿用模拟审批或模拟质量结论。

## 2. 支持的连接器目录

| 连接器 ID | 代码 | 系统 | 主要只读能力 | 预留写能力 | 环境变量前缀 |
| --- | --- | --- | --- | --- | --- |
| `tos` | TOS | 码头操作系统 | 船舶挂靠、泊位计划、堆场库存、设备任务、作业指令 | 泊位计划、岸桥计划、调度指令 | `XIAOYI_CONNECTOR_TOS_` |
| `pcs` | PCS | 港口社区系统 | 港口挂靠、货物状态、参与方、单证状态 | 社区消息、服务申请、单证交换 | `XIAOYI_CONNECTOR_PCS_` |
| `ems` | EMS | 能源管理系统 | 计量数据、能源基线、岸电、碳指标、能源告警 | 告警阈值、需求响应计划 | `XIAOYI_CONNECTOR_EMS_` |
| `eam` | EAM | 企业资产管理系统 | 资产台账、设备状态、故障、维修工单、备件 | 维修工单、点检任务 | `XIAOYI_CONNECTOR_EAM_` |
| `vts` | VTS | 船舶交通管理系统 | 交通态势、船舶动态、航行警告、交通计划 | 安全消息草案、交通计划建议 | `XIAOYI_CONNECTOR_VTS_` |
| `ais` | AIS | 船舶自动识别系统 | 船位、船舶静态数据、航次、轨迹 | 无，框架强制只读 | `XIAOYI_CONNECTOR_AIS_` |
| `weather` | METOC | 港区气象与海洋环境服务 | 实况、预报、预警、风浪流、能见度 | 无，框架强制只读 | `XIAOYI_CONNECTOR_WEATHER_` |
| `single-window` | SW | 国际贸易单一窗口 | 申报、舱单、查验、放行状态 | 申报、舱单、申报更正 | `XIAOYI_CONNECTOR_SINGLE_WINDOW_` |

表中的能力是通用接入分类，不代表任何具体厂商或主管部门已经提供对应接口。最终能力、报文和权限必须以站点正式接口文档为准。

### 2.1 TOS

TOS 接入重点是统一船舶挂靠标识、箱号、泊位、作业机械和任务状态。不同码头 TOS 的对象命名、状态机和计划版本差异很大，应先从船舶计划、设备状态等只读数据开始。泊位、岸桥和调度写入具有直接生产影响，必须由调度岗位确认并通过站点变更流程。

### 2.2 PCS

PCS 涉及港口、码头、船公司、货代、海关及物流参与方。接入前应明确数据所有权、共享范围、参与方标识、报文标准、回执机制和数据留存要求。单证交换不能只依据 HTTP 成功判断完成，必须核验业务回执和最终状态。

### 2.3 EMS

EMS 数据要统一计量点、采样周期、时区、单位、倍率和质量码。电量、功率、岸电和碳排数据不能混用；碳指标还必须记录排放因子版本、核算边界和来源。阈值或需求响应计划写入前，应评估对生产设备和能源控制策略的影响。

### 2.4 EAM

EAM 接入要统一资产编码、位置层级、故障代码、工单状态和责任班组。智能助手可以生成工单草案，但不得绕过维修审批、作业许可、隔离挂牌或安全确认直接改变设备状态。

### 2.5 VTS

VTS 属于高敏感安全监管系统。原则上采用最小范围、只读、隔离网络接入。交通组织或安全消息写能力只作为未来适配点，必须取得主管机关授权，并保留值班员复核、消息签发和完整审计；智能助手不能替代法定值班职责。

### 2.6 AIS

AIS 连接器按只读方式设计。接入时应处理重复报文、异常跳点、信号延迟、MMSI/IMO 关联、A 类与 B 类报文差异，并明确岸基 AIS、卫星 AIS 或商业聚合数据的许可证和使用边界。AIS 不是单独的避碰或监管结论来源。

### 2.7 METOC

气象海洋数据连接器 ID 为 `weather`，环境变量使用 `WEATHER`。应明确观测站、预报模式、空间范围、更新时间、预警发布机关、时效和单位。第三方预报不能替代法定预警；生产决策必须展示来源、发布时间和有效期。

### 2.8 SW

国际贸易单一窗口连接器 ID 为 `single-window`，环境变量使用 `SINGLE_WINDOW`。正式接入必须遵循主管部门身份认证、报文签名、传输、回执和留存规范。申报与更正属于高风险外部行为，必须核验申报主体、授权人员、业务回执和最终放行状态。

## 3. 运行模式

每个连接器独立配置 `MODE`：

| 模式 | 外部访问 | 可标记 online | 可通过写预检 | 用途 |
| --- | --- | --- | --- | --- |
| `offline` | 否 | 否 | 否 | 默认安全状态、停用、回滚 |
| `demo` | 否 | 否 | 否 | 仅用于界面和流程演示 |
| `live` | 健康检查会访问配置的端点 | 仅真实健康请求成功后 | 仍需其他全部门禁 | 已授权站点联调或生产接入 |

`demo` 绝不等于测试环境在线，`live` 也不自动等于 `online`。当 `MODE=live` 但地址、认证或凭据不完整时，连接器返回 `misconfigured`；尚未执行健康检查时返回 `unchecked`。

## 4. 环境变量与安全配置

安全模板见项目根目录的 [`.env.connectors.example`](../.env.connectors.example)。每类连接器均使用以下变量：

| 后缀 | 说明 | 安全默认值 |
| --- | --- | --- |
| `_MODE` | `offline`、`demo` 或 `live` | `offline` |
| `_BASE_URL` | 站点授权的 HTTP/HTTPS 基础地址 | 空 |
| `_AUTH_TYPE` | `none`、`api_key`、`bearer`、`basic`、`oauth2`、`mtls` | `none` |
| `_CREDENTIAL` | 服务端凭据；API 只返回是否已配置，不返回内容 | 空 |
| `_ALLOW_WRITE` | 服务端写权限总开关 | `false` |
| `_HEALTH_PATH` | 相对基础地址的健康检查路径，必须以 `/` 开头 | `/health` |
| `_TIMEOUT_SECONDS` | 健康检查超时，允许 0.2—15 秒 | `3` |

例如 TOS 使用 `XIAOYI_CONNECTOR_TOS_MODE`，气象使用 `XIAOYI_CONNECTOR_WEATHER_MODE`，单一窗口使用 `XIAOYI_CONNECTOR_SINGLE_WINDOW_MODE`。

应用从**进程环境变量**读取配置，不会自动加载 `.env.connectors.example`。本地隔离联调可以复制为不纳入版本控制的私有文件后，通过受控启动脚本或部署平台注入；生产环境应使用密钥管理系统、容器 Secret 或等效机制，禁止将真实凭据写进仓库、日志、聊天记录、浏览器存储或前端代码。

### 4.1 认证说明

- `api_key`：当前通用健康检查使用 `X-API-Key` 请求头。若站点使用不同头名，必须实现站点适配器。
- `bearer`：将已有访问令牌放入 `Authorization: Bearer ...`。不要把用户名密码误填为令牌。
- `basic`：`CREDENTIAL` 格式为 `username:password`，运行时进行 Base64 编码；只允许在 TLS 和获批网络中使用。
- `oauth2`：当前框架把 `CREDENTIAL` 视为已签发的访问令牌，尚未实现令牌获取、刷新或客户端凭据流程。
- `mtls`：目录保留了 mTLS 能力，但当前通用健康检查尚未装载客户端证书和私钥。站点必须实现专用 TLS 上下文/适配器后才能使用，不能仅填写 `CREDENTIAL` 就宣称已完成 mTLS 接入。
- `none`：只适合站点明确允许匿名访问的 AIS 或气象类只读服务；其他连接器在 `live` 下会被配置校验拒绝。

基础地址禁止内嵌用户名和密码。网络侧还应配置 DNS、出口白名单、IP 白名单、TLS 证书校验、代理策略和最小访问范围。

## 5. API 与健康检查

```text
GET  /api/connectors                              连接器目录与安全状态
GET  /api/connectors/{id}                         单个连接器详情
GET  /api/connectors/{id}/field-mappings          字段映射模板
GET  /api/connectors/{id}/health                  执行健康检查
POST /api/connectors/{id}/health-check            执行健康检查
POST /api/connectors/{id}/write-preflight         写操作安全预检，不执行下发
```

健康状态含义：

- `offline`：未启用，或真实健康请求失败。
- `demo`：演示模式，没有访问生产系统。
- `unchecked`：`live` 配置已加载，但尚未实际检查。
- `online`：本次实际 HTTP 健康请求返回成功。
- `degraded`：目标可达，但返回异常 HTTP 状态。
- `misconfigured`：模式、地址、认证、凭据、路径或超时配置不合法。

`live_data_verified: true` 仅表示健康端点响应成功，不能证明业务记录真实性。正式验收还要核对业务接口、事件时间、数据条数、校验和、源系统记录和业务回执。

离线检查示例：

```bash
curl -s http://127.0.0.1:8010/api/connectors
curl -s -X POST http://127.0.0.1:8010/api/connectors/tos/health-check
```

在默认模板下，目录应显示 8 个连接器全部 `offline`、`online=0`、无真实地址、无凭据、写权限关闭。

## 6. 字段映射治理

API 返回的 `mapping_version: draft-1` 和字段映射仅是规范化数据模型的起点，不是任何厂商接口的已确认数据字典。每个站点必须形成经双方签字或版本化审批的映射表，至少包含：

- 规范字段、源字段、方向、数据类型、是否必填和业务含义；
- 唯一键、关联键、枚举值、状态机和删除/撤销语义；
- 时区、时间精度、坐标系、单位、倍率、币种和小数精度；
- 空值、默认值、异常值、质量码和迟到数据处理；
- 全量/增量方式、游标、水位线、重放和幂等键；
- 字段来源、数据责任人、敏感等级、脱敏和保留期限；
- 接口版本、映射版本、兼容策略和变更生效时间。

映射上线前要用源系统样本进行正向转换、逆向核对和边界值测试。关键指标应同时对比源系统界面、接口结果和小懿侧结果，达到站点约定的对账阈值后才可验收。

## 7. 站点联调流程

建议按以下阶段推进，每一阶段都有明确退出条件：

1. **授权与范围确认**：确定系统所有者、数据责任人、网络边界、读写范围、使用目的、保留期限和审批人。
2. **接口盘点**：取得正式接口文档、数据字典、错误码、限流、SLA、证书链、测试账号和变更通知机制。
3. **隔离环境联调**：在厂商或港口方测试环境完成认证、健康检查、分页、限流、超时、重试和错误处理。
4. **只读影子运行**：生产网络只开只读权限，持续对账，不让结果参与自动控制或对外申报。
5. **数据验收**：验证完整性、准确性、及时性、唯一性、一致性和可追溯性；记录映射及样本证据。
6. **故障演练**：覆盖超时、断网、凭据失效、重复消息、乱序、接口降级、源系统回滚和版本升级。
7. **受控写入试点**：仅在确有必要且获批时启用，限制对象、操作、时段、频率和审批人员，先从非生产或低风险动作开始。
8. **生产验收**：完成安全评审、业务验收、运维交接、监控告警、回滚预案、值班表和应急联系人确认。

推荐的只读验收指标包括接口可用率、P95 延迟、数据延迟、字段空值率、重复率、源端/目标端条数差异和关键业务字段一致率。阈值由站点和系统所有者共同确定，不能使用虚构的“行业统一阈值”。

## 8. 写操作门禁

当前 `/write-preflight` 必须同时满足：

1. 操作在该连接器声明的写能力内；
2. 请求包含明确的人工确认：`confirmed=true`、`operator_id`、`reason`、`reference`；
3. 连接器为 `live`；
4. 配置无错误；
5. 服务端 `ALLOW_WRITE=true`；
6. 最近一次真实健康检查为 `online` 且 `live_data_verified=true`。

上述条件只允许生成短时写预检标识，并不代表站点生产准入。还必须满足
`data/contracts/port_site_admission_v1.json` 的现场字段映射、标定、漂移、
影子运行、双人审批、回滚演练和OT/IT安全门禁；当前七项均为
`blocked_pending_site`，因此生产调度权限保持关闭。

预检通过后只生成 60 秒有效的授权标识，仍然返回 `dispatch_performed: false`。当前框架没有通用生产下发端点。

正式站点适配器在执行任何写操作前，还必须增加：

- 企业统一身份认证、RBAC/ABAC 和最小权限；
- 高风险操作双人复核或四眼原则；
- 目标对象、字段、数值范围、时间窗和频率白名单；
- 幂等键、请求签名、防重放、超时和业务回执校验；
- 写前快照、写后读取核对和失败补偿；
- 不可篡改的持久审计日志；
- 紧急停止开关及站点人工接管路径。

客户端传入 `confirmed=true` 本身不能证明操作者身份。只有接入可信身份系统并校验岗位、权限和审批流后，才可以把它视为有效人工确认。

## 9. 回滚、停用与故障处置

连接器出现异常时，按影响范围从快到慢执行：

1. 将对应 `_ALLOW_WRITE` 设置为 `false` 并重启/滚动更新服务；
2. 将对应 `_MODE` 设置为 `offline`；
3. 在网关或防火墙撤销出口和目标白名单；
4. 在源系统吊销令牌、密钥或证书；
5. 停止相关自动化任务，转人工流程；
6. 对已执行动作读取源系统最终状态并逐笔对账；
7. 保存日志、请求标识、审批记录、业务回执和时间线，启动事件复盘。

业务写操作不应简单发送“反向命令”作为回滚。泊位、调度、工单和申报数据都有各自的状态机，必须使用源系统认可的撤销、更正或补偿流程，并由业务负责人批准。

恢复前应完成根因分析、凭据轮换、数据修复、回归测试和再次审批。恢复顺序建议为 `offline` → 只读 `live` → 小范围受控写入，禁止直接恢复全量写权限。

## 10. 审计与证据留存

当前内存预检只返回授权标识，尚未实现持久化、不可篡改的生产审计库。启用真实写入前必须补齐审计服务，至少记录：

- 连接器、环境、接口和操作名；
- 业务对象标识及脱敏后的请求摘要/哈希；
- 操作者、岗位、审批人、审批单号和确认时间；
- 自动化计划 ID、步骤 ID、提示词/规则/模型版本；
- 写前状态、请求时间、响应码、业务回执、写后状态；
- 幂等键、关联 ID、重试次数、失败原因和补偿结果；
- 配置版本、字段映射版本、部署版本和证书指纹；
- 来源系统时间、平台接收时间、审计落库时间和统一时区。

日志不得直接保存密码、令牌、私钥或完整敏感报文。留存周期、访问权限、脱敏和销毁要求由港口方的数据分类分级、网络安全、档案和监管制度确定。
