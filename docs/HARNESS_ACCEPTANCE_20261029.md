## 已实现能力与边界

| 能力 | 当前实现 | 限制 |
| --- | --- | --- |
| 模型与工具循环 | 绑定工具名及参数的结构化动作；模型接收真实工具反馈；规则模式另行标识 | 只实际验证当前本地模型；其他兼容服务需单独联调 |
| 计划与完成条件 | 首次计划、约束或失败变化后的修订、必需工具合同、无进展检测 | 有明确必需工具时使用有界证据流程；开放研究需显式 `required_tools=[]` |
| 状态与恢复 | SQLite事务、检查点、90秒租约与心跳、读操作恢复、未决副作用隔离 | 当前4个本机工作线程；没有多日耐久性或多机负载证据 |
| 人工介入 | 追问、运行中约束、暂停、取消、继续、绑定摘要和有效期的审批 | 取消不会撤销已发出的目标请求；暂停在当前I/O安全边界生效 |
| 审批与身份 | 事件持久保存审批人、角色、审批ID与动作摘要；代办保留原所有者执行权限 | 沿用项目身份体系；未接企业IAM和外部电子签名 |
| 工具与工件 | 9个登记工具、严格参数、任务隔离、保留名防覆盖、AST受限计算 | 虚拟工件在SQLite中；无任意主机文件、Shell或Python执行 |
| 上下文与记忆 | 原目标及全部补充约束保留；大结果摘要与原始工件并存；技能冻结版本；显式用户记忆可删 | 模型不能自动写长期记忆；没有更新模型权重 |
| 并行研究 | 最多3个只读/纯计算分支，子权限和预算逐项检查，保留部分成功 | 不是通用自主多智能体系统 |
| MCP | 只读工具服务端、身份与Origin检查、登记协议版本及元数据校验 | 无任意远程MCP客户端、OAuth授权服务器、采样或订阅；仍需第三方互操作验收 |
| 轨迹和核验 | 事件游标/SSE、工件、来源、预算、JSON导出、本地摘要链、引用与数值检查 | 本地一致性不是外部防篡改签名；数值存在性不是语义、单位或因果正确性证明 |
| 联动操作 | 复用原方案预览、审批、执行、回读与恢复；未知写结果只读核查，不盲目重放 | 原目标锁仍是单进程；不能承诺分布式恰好执行一次 |

远程模型必须显式允许外发、使用HTTPS并配置密钥；模拟和联动证据继续保留本机处理边界。所有生产权限保持关闭，公开资料、离线计算与工程模拟均保留来源标识。

## 缺陷修复与失败证据

实际模型联调中发现并修复了：结构化语法不兼容、工具与参数错配、原生时间对象序列化、组合任务漏读、重复同义规划、模型把当前模拟港区误当成缺少地点、无关工具反复读取，以及轻量模型输出过长导致预算耗尽。

运行层还验证并修复了：最后允许工具调用后的交付、并行部分成功计数、结果工件保留名覆盖、输入与旧决策竞争、已批准未执行方案被新约束撤销、重复读取与新观测区分、审批人记录清理后丢失，以及管理员代办时错误提升任务角色。

10月28日早期失败报告保留在原证据目录，`model-default-profile-v1` 至 `v5` 不作为成功证据；默认配置成功记录为 `v6`。旧报告已标记为历史版本，避免把早期状态当成当前结论。
