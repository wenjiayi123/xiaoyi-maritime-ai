# 小懿 1.7B 工具决策实验第二轮：方法与证据边界

本轮从 2026-11-01 保存的 SFT 检查点继续研究。第一轮独立测试 C=11/24、D=10/24，真实系统联合任务也失败；这些证据完整保留，不将负结果替换成新成绩。

## 研究问题

在相同工具、状态信息、候选动作和任务步数预算下，使用环境回报进一步更新语言模型参数，能否改善同一个 SFT 模型的任务完成率、参数匹配与异常恢复？同时用继续 SFT 对照，检查收益是否仅来自额外训练。

这是可在 Intel Mac CPU 上运行的受约束研究实验。模型为 Qwen3-1.7B，只有最后四层注意力 q/v 投影的 229,376 个 LoRA 参数参与训练。默认 4B 日常模型不参与本轮训练。

## 各部分的工作

- 语言模型看到任务、已完成事项、尚缺条件、最近反馈和 13 个动作候选，给出一个字母。
- Harness 按注册表把字母转换为工具与参数，执行、核验、把结果返回模型。全部组使用相同版本。
- 实际系统入口先用登记解析器提取任务族和数值，再把规范化任务交给模型。本轮未验证任意自然语言理解；数字参数为候选选择，不是自由生成。
- SFT 使用规则专家给出的正确动作作为示范，最小化交叉熵。
- 本轮 RL 在可复位模拟环境中枚举每个动作及随后一步的结果，根据环境奖励更新模型的动作概率。推理时不运行此枚举，不提供奖励或专家答案。

本轮方法是**两步模型式 actor 优化**，使用完整有限动作集的期望目标。它不是长时域 PPO/GRPO，也不是自由生成任意 JSON、任意数字参数。优化程序、状态采样与奖励设计均属于应用研究，不能宣称提出了新的基础 RL 算法。

## RL 目标与奖励

对训练状态 s 和候选 a，在模拟器里计算：

`Q₂(s,a) = r(s,a) + max_b r(s_after_a,b)`，第一步结束任务则后项为 0。

先将同一状态的 13 个 Q₂ 值中心化并标准化，再最大化模型动作分布下的期望值；同时施加对冻结 SFT 分布的 KL 约束和小幅熵奖励。优化器是 AdamW；温度 2、学习率 0.0002、KL 系数 0.02、熵系数 0.001、梯度裁剪 1。具体配置以运行目录的 `config.json` 为准。

每步奖励由以下可重算分项组成：动作成本 −0.1；无效动作 −0.2；状态无进展 −0.2；完成任务 +3；预算耗尽失败 −1；进展势函数项 `2*(Phi_after-Phi_before)`。Phi 按本任务必需的读取、计算、暂停恢复、核验等事项完成程度计算；终止时 Phi 固定为 0。完整轨迹中的势函数项相互抵消，避免仅凭进展累计获得虚假成功。

两步视野用于识别“首次读取超时，但重试后可成功”的价值。它不能保证解决长任务，也不能保证代理目标上升就带来完整任务完成率上升，必须用闭环任务独立检验。

相关基础方法：[策略梯度](https://papers.nips.cc/paper_files/paper/1999/hash/464d828b85b0bed98e80ade0a5c43b0f-Abstract.html)、[势函数奖励塑形](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)、[全动作策略梯度](https://arxiv.org/abs/1910.09093)。本实现的有限视野近似不继承完整长期最优性的保证。

## 对照与数据分区

| 组别 | 行为来源 | 额外训练 |
|---|---|---|
| A | 完整固定规则 | 无 |
| B | 原始 1.7B | 无 |
| C | 昨日冻结 SFT | 无 |
| D | 与 C 相同起点，继续 RL | 环境回报 |
| E | 与 C 相同起点，继续 SFT | 正确动作标签 |

训练集 48 案例、验证集 16 案例、最终测试集 24 案例，均涵盖 8 个已知任务族。训练状态池包括 210 个示范路径状态和 96 个错误交付后的恢复状态；D、E 使用相同状态、顺序、学习率与更新步数上限。D 的目标函数不读取 SFT 标签，E 不读取奖励向量。

验证检查点为 128、256、512 步。选择顺序：完成数更多、错误更少、调用更少、步数更早；固定 8 题能力回归至少保持 C 水平。仅在达到验证集全部完成、无额外可避免错误且回归保持时提前停止。两组实际用时与最终更新数分别报告，不能称计算量完全相等。

开发阶段修订：RL 的 512 步版本验证任务达到 11/16（C 为 9/16），但固定回归下降到 7/8，因此不满足选择门槛。2026-11-02 09:49（+0800）在最终测试未打开时，登记了相同的 64、128、192、256、320、384、448、512 步筛选网格，分别用于 D、E 已保存的检查点。先筛能力保持，再对符合条件的新检查点做完整任务验证；不新增训练，不修改奖励、数据或参数。保留原选择文件和所有不合格结果。这是明确披露的开发阶段协议修订，不能声称从一开始就采用该网格。

另在修订筛选执行前冻结 20 道新能力检查题，最终选择后测一次，不参与训练、选择或继续调参。包含单位、算术、数据来源、零值、调用异常与约束处理。部分概念与原检查相近，二选一题也有限；它提供额外保持证据，不构成全面通用能力基准。

最终测试在冻结检查点选择文件后用独立命令打开，训练命令不读取测试案例。任务参数网格分离，开头措辞分离；并非未知任务结构、陌生工具或复杂自然语言泛化。查询类流程仍高度相似，24 个案例不是 24 种互不相关的业务能力；不据此推导大范围统计结论。

新一轮加强了所有组的事实反馈、改变了候选干扰参数和奖励。比较 RL 收益必须看本轮的 D−C、D−E；不能把跨轮分数变化全部归因于 RL。

指标口径：任务成功必须在调用预算内完成所有要求、通过核验并交付报告。`total_errors` 是返回失败的动作次数，包括明确注入的故障；合法但无进展的重复动作不算入这个数，因此不能仅用报错次数评价全部行为。平均调用次数包含失败任务；恢复率的分母包含所有分配到的故障案例，不能只挑实际触发故障的成功案例。

## 原始证据与复现

目录：`.codex_artifacts/agent-rl-v2-20261102/experiment-004/`。

- `config.json`、`task-manifest.json`、`source/`：配置、数据分区与实际运行源码快照。
- `training-states.json`、`counterfactuals/`：完整输入、状态历史、所有候选的模拟分支和奖励；模拟枚举明确标为非模型实际行动。
- `training.jsonl`：每次更新的概率、损失、梯度、KL、熵、时间、参数摘要；奖励曲线须注明是两步代理回报。
- `frozen-reference-logits.jsonl`：冻结 SFT 的参考输出。
- `checkpoints/`：LoRA、优化器、随机数状态与检查点摘要；每 32 步保存。
- `trajectories/`、`evaluations/`、`retention/`：验证与最终测试的全部成功、失败、输入、动作及结果。
- `checkpoint-selection.json`、`test-opened.json`：先选模型、后开测试的记录。
- `selection-grid-amendment.json`、`checkpoint-selection.pre-refinement.json`、`selection-refinement-candidates.json`：筛选修订、原选择、所有中间候选。
- `retention-holdout-manifest.json`、`retention-holdout-decisions.jsonl`：新能力检查题的预先冻结记录与所有实际决策。
- `audited-summary.json`：独立重放核验后才能使用的结果。

冻结前 24 层的中间激活只用于精确 CPU 加速，按输入与基础模型身份保存磁盘缓存。学习层始终使用当前参数。完整计算与缓存的输出/梯度必须验证一致，不能把旧预测冒充新模型输出。

硬件补充探测确认本机 Radeon Pro 560X 有 4GB 显存，PyTorch 2.2.2 的 MPS 后端可用；一个真实 Qwen3 层、57,344 个继承的 LoRA 参数完成了 MPS 前后向，数值容差检查通过。本轮正式实验仍为 CPU。单层探测不是完整模型训练验证；其 CPU 探测只用一线程且正式 CPU 训练正在并发运行，不可据此宣称整轮 GPU 加速倍数。D 先运行并承担首次缓存生成，E 复用缓存，因此耗时也不是严格同条件速度基准。
