# 小懿 Harness：当前能力、实测、修复与展示说明

日期：2026-10-31。工作目录：`/Users/apple/Desktop/小懿AI`。本轮全部原始证据位于 [full-demo-v11-20261031](../.codex_artifacts/full-demo-v11-20261031/)。

## 结论

小懿已经具备**可实际演示的港航业务任务运行层**：能连接本地模型与登记工具，保存任务状态，执行有边界的业务流程，处理审批和恢复，并导出可核对的过程与结果。最有价值的是“从目标到可检查业务结果”的工程闭环。

它目前属于**本机、公开数据与工程模拟条件下的集成原型**。尚未达到真实港口生产准入；复杂自由生成的正确性、长时间开放任务稳定性与跨站点泛化仍有限。不能把“流程跑通”表述为“4B自主完成所有规划”，也不能把测试通过率表述成模型答案准确率。

Harness 可以通俗理解成模型的“工作台、工具箱、进度本和检查员”。长任务需要持久状态、清晰完成条件及实际端到端检查；评估需要核对最终状态而不只看回答是否流畅。这与 Anthropic 的 [长任务 Harness 研究](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)和[智能体评测说明](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)一致。这些资料用于确定评审维度，不是第三方对小懿的认证。

## 本轮发现与修复

| 问题与根因 | 改进 | 如何核验 |
| --- | --- | --- |
| 原200字符硬约束造成半句截断，但状态显示完成 | 180字生成目标、400字符传输上限；字符封顶/token截断进入有界修正且照常计费 | 真实失败回执保留；截断与格式回归反例；新模型任务 |
| 4B向用户索要本机已可读取快照，后续无进展 | 合同要求且读取未失败时先执行无需参数的快照读取，再允许必要追问 | 实际复测自行取得快照和SOP；失败后追问仍允许 |
| 自定义快照任务可能绕过业务模板的交付时效核验 | 所有成功原生快照都在交付时检查，保留120秒门槛 | 新鲜/121秒过期/有明确历史限制三类测试；实际233.7秒任务被要求补充暂缓说明 |
| 模型把有告警的快照写成“均正常”，或无检验却声称“未发现显著差异” | 对原始快照矛盾放行和无根据统计声明增加拦截；允许明确否定式限制 | 五个正反例；仍不宣称完成全部语义验证 |
| 后台慢初始化可能把用户已打开的知识库或训练页切回聊天 | 恢复欢迎态仅限当前仍在聊天且无用户活动 | 前端延迟初始化回归覆盖多个视图 |
| 小屏导航重叠、关闭抽屉仍可聚焦 | 小屏导航布局及隐藏面板可见性/点击控制；导航后关闭侧栏 | 实际UI操作与前端回归 |
| 暂停点击后缺乏即时解释 | 明示“等待当前调用到达安全边界”，恢复显示成功状态 | 实际模型暂停/继续演示 |
| 演示服务缺少本地模型、原生航行与移动端连接 | 启动并验证现有4B权重，设置登记Godot路径，按本机API重建Flutter演示产物 | 权重摘要、模型接口、原生航行回执、移动端实际签收 |

这些改进不改变模型权重、RL奖励、MPC比较口径、年度孪生阈值或预测验收门槛。当前证据不足以将所有限制归因于4B体量：工具可见性、上下文、截断和时效都是可改进的工程因素；自由语义推理仍需独立评价。
