# 小懿 1.7B 多任务工具决策：方法与复现实验

## 研究对象

本实验研究语言模型在有状态工具环境中的下一步选择。任务覆盖港口查询、能碳比较、港口情景、交通查询、联合评估、读取超时、回执丢失和模拟状态恢复。训练环境为可复位的合成工具工作流，原系统的真实 API 验收另行进行。

输入包含经登记模板规范化的用户目标、明确参数、已完成操作、核验与恢复状态、最近工具反馈和剩余预算。模型在 13 个已展示的工具及参数候选中生成一个动作字母，Harness 将字母映射到展示过的结构化调用。四组共享此输入和动作空间。

候选参数的枚举、任务参数提取、Schema 校验、数值计算、证据保存及最终报告排版属于工程能力。模型学习选择候选与执行顺序。本轮没有验证自由生成任意 JSON、任意数值参数、未登记工具或未知业务类别。

自然语言入口先以登记关键词和数值解析为任务规格，再向模型提供规范化任务描述。故本轮并未验证任意改写指令的理解能力。模型主要读取工作流状态；业务数值由原系统计算并进入证据报告，不将这些计算记为语言模型推理成果。

## 模型参数确实在哪里变化

- 底座：本机已缓存的 Qwen3-1.7B，具体固定快照见每次运行的 config.json。
- 冻结预训练底座，只在最后四个 Transformer 层的 q_proj、v_proj 中训练 LoRA。
- rank=8，alpha=16，dropout=0；共 229,376 个可训练参数。
- 策略分布来自这个语言模型下一 token 的 logits，在动作字母集合上归一化；没有用另一个分类网络替代语言模型。
- 分别保存 SFT 和 RL 的 PEFT safetensors 检查点，记录适配参数摘要；运行服务检查实际加载参数与对照组摘要一致。
- 原 4B GGUF、旧 1.7B LoRA、已有下层 SAC/PPO 等业务模型不被替换。

## SFT 与 RL

SFT 使用训练分区中确定性参考策略生成的正确过程示例。参考策略也是 A 组，不刻意削弱它。SFT 目标为正确动作字母的交叉熵。

RL 从同一个 SFT 检查点开始。同一个任务采样多个完整尝试，依据实际环境结果计算回报，将组内回报标准化为优势。对模型选择的动作应用裁剪策略梯度，同时加入相对于 SFT 策略的离散 KL 正则与小幅熵正则。每组执行一次优化器更新，梯度裁剪为 1。

这是**受约束离散动作上的组相对策略梯度实验**，不是完整自由文本 token 级 GRPO 框架，也不声称提出了新的 RL 算法。算法思想参考 [PPO 原论文](https://arxiv.org/abs/1707.06347)；LoRA 使用 [PEFT 官方实现](https://huggingface.co/docs/peft/package_reference/lora)。

每组仅执行一次优化器更新，没有对旧轨迹进行多轮 PPO 更新；在本轮更新前，新旧策略比率接近 1，不能把裁剪项描述成已经验证的主要稳定性来源。各采样组轮换不同任务，因此训练回报折线仅记录实际训练信号，不作为收敛或独立效果证明。

任务回报由独立条件检查产生：所需观测是否齐备、采用的参数是否正确、结果是否已读回、原状态是否恢复，以及能否生成有依据的报告。重复动作没有正奖励；无效操作、过早交付和超预算受到惩罚。成功来自环境状态，不能由模型自称完成。

## 本机计算优化

前部 Transformer 层完全冻结。对同一输入缓存它们的输出，在后续前向/反向计算中复用；可训练的末尾四层继续按当前权重实际计算。缓存有容量上限，模型保存前恢复完整模块结构。另对相同参数摘要和相同输入的推理结果作精确缓存。

启用前必须比较完整计算与缓存计算的 logits 和全部可训练参数梯度。`cpu-cache-verification.json` 记录核对值。缓存不会使用测试答案，也不会将一个模型的输出缓存冒充另一个模型的输出。

## 四组与独立测试

| 组别 | 策略 |
|---|---|
| A | 有明确状态处理的确定性参考规则 |
| B | 原始 1.7B 模型，同样的工具和动作候选 |
| C | SFT 后的 1.7B 模型 |
| D | 从 C 继续进行 RL 的 1.7B 模型 |

B 是原始 Qwen3-1.7B 在相同单动作、关闭思考文本的输出模式下的对照，不代表现有 4B 小懿、旧港航适配器或其他推理方式的能力。四组的任务执行均不使用外部大模型代做。

训练/验证/测试规模为 48/16/24 个案例。测试保留未见数值组合，八类任务与工具都是已知类别。测试案例的初始输入彼此不同，与训练、验证无交叉；训练分区存在部分重复输入，未计为独立测试样本。

独立测试只在训练结束后进行。开发验收指令与测试集分开。每个模型在相同最大步数下按最高概率选择动作。任务完成率、参数尝试正确率、全部故障任务的恢复率、调用步数及八道固定回归题分开报告。没有参数尝试时正确率为无数据，不能填作一次错误尝试。

参数尝试正确率逐项比较基准偏好、候选偏好和碳价三个字段，独立于是否已读取前置观测。参数正确但缺少前置步骤，计为参数匹配、执行失败；原始环境的成功参数执行计数另存为 `parameter_execution_success_rate`。这避免将流程错误混入纯参数匹配指标。

结果审计程序依据原始动作重新运行环境，不调用模型、不更新参数、不改变原记录。全部四组须使用相同测试案例；图表从审计后的 JSON 生成。95% Wilson 区间只显示小样本不确定性，单训练种子与模板相关性不足以支持普遍优势或统计显著性声明。

## 真实系统验收

在实验页输入实施计划中预登记的联合指令，由 1.7B 模型选择下一步，分别调用本机港口、能碳与马六甲原生 API。可明确注入一次读取超时，并检查模型能否继续完成。模型权重身份、每次动作、失败、原始响应、摘要、参数回写和结果文件都保留。

报告的数值和表格由已核验事实确定性编制；不能把排版或 Harness 自动清理计为模型学会的操作。不同系统的地点、时钟、公开数据和工程假设分别显示；不将联合查询解释为现场联合控制或新的业务 RL 增益。

## 可复现命令

在已有完整底座与独立 `.venv-lora` 环境下，从头训练：

```bash
.venv-lora/bin/python scripts/run_agent_rl_v1.py \
  --output .codex_artifacts/agent-rl-reproduction \
  --sft-steps 240 --sft-lr 0.0002 \
  --rl-groups 16 --group-size 3 --temperature 2.0
```

复现实验使用新的输出目录，避免覆盖既有记录。从完整 SFT 检查点继续训练可使用 `--resume-sft <父实验目录>`；父实验数据分区必须匹配，检查点来源及原训练日志被保留。

```bash
.venv/bin/python scripts/audit_agent_rl_results.py --experiment <实验目录>
.venv/bin/python scripts/render_agent_rl_report.py --experiment <实验目录>
.venv/bin/python scripts/start_agent_rl_v1.py --experiment <实验目录>
```

训练使用现有 Python 3.9 / PyTorch 2.2.2 环境；Web、审计和绘图使用项目 Python 3.12 环境。绘图额外依赖 Matplotlib，实际版本保存在图表来源记录中。本机实验的结果不能直接冒充 4B 的训练成果。

## 后续迁移 4B

可以复用任务定义、工具接口、奖励检查、轨迹格式和评测程序。4B 需要用匹配其层数与张量维度的适配器重新训练、重新验收，不能把 1.7B 的 LoRA 文件直接称作 4B 权重。当前实验入口仅在登记工具任务中加载实验适配器；原小懿日常问答继续使用原模型。这种部署隔离保护原服务，但不等于证明实验适配器本身没有能力退步。
