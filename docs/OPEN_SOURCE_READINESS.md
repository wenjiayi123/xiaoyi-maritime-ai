# 开源前真实性与工程化评估

更新时间：2026-07-24

## 已处理

| 板块 | 原问题 | 当前处理 |
|---|---|---|
| RL训练 | 读取其他项目历史曲线并加速回放，前端无法证明是真训练 | 本仓库内真实执行4种RL算法；后台episode计数驱动进度；模型和配置落盘并计算哈希 |
| 算法基线 | 外部接口或固定公式返回所谓赛马结果 | Q-learning、SARSA、Expected SARSA、Double Q-learning共享环境；PID作为独立控制理论基线 |
| 训练/渲染 | 训练曲线和视觉回放混在同一链路 | 代码强制训练`render_mode=None`；训练完成后测试接口才读取保留测试段并返回trace |
| 数据集 | 动态沙箱或外部系统契约，无法让GitHub用户复现 | 内置UCI真实公开数据、CC BY 4.0归属、固定下载脚本、原始/派生SHA-256和转换记录 |
| 港口数据替换 | 参数散落在外部项目 | 统一CSV契约；必填`timestamp,load_kw`，可用环境变量做列映射，无需改训练器 |
| 旧高级RL | MAPPO、MAS和孪生效果来自外部本机项目，仓库内没有环境/训练/检查点 | 页面入口移除，API返回`410 Gone`；满足完整可复现条件前不恢复 |
| 普通任务进度 | 点击一步只返回固定展示文案 | 每一步真实读取当前数据源并计算峰值、告警数、资源数；启发式明确标注不是数学最优解 |
| 报告 | 固定写“整体平稳”等结论 | 根据本次KPI、能耗点和告警数量生成；写入数据模式、质量码和`live_data_verified` |
| 跨系统中枢 | 默认`demo`容易被误读为在线 | 默认改为`offline`；只有显式`live`才允许登记的GET只读调用 |
| Web安全默认 | CORS允许任意来源并带凭据 | 改为显式本地来源白名单，默认不允许跨域凭据 |
| 仓库卫生 | 运行库、日志、软著模板和本机产物可能进入Git | 新增`.gitignore`，排除数据库、日志、模型运行产物、凭据和软著工作区 |
| 身份与权限 | 本地身份头可由调用方自报 | 生产模式验证签名JWT，按viewer/analyst/operator/admin映射权限，忽略客户端伪造的执行人字段 |
| 可靠性 | 对话、任务、报告和自动化重启即丢失 | SQLite持久化；未完成工作重启后安全标记失败或取消，不静默续跑 |
| 可观测性 | 只有浅层健康接口 | 深度就绪、Prometheus指标、JSON日志、请求ID和前端分项系统状态 |
| 供应链 | 缺少发布门禁 | 锁定依赖、容器、CI、Dependabot、PR依赖审查、数据血缘和凭据扫描 |
| RAG指标 | 25题内置回归过小且没有同快照基线，100%难以解释 | 增至60题固定版本集；35题测试分区只报测试指标；同口径对比BM25-only并发布逐题结果、核心代码/索引/数据SHA-256 |
| 证据安全 | 沙箱问答可能抢先接管生产标识，复核日期被误作法律失效日期 | 显式实时资产查询失败关闭；条款级请求要求官方全文；法律生效区间与来源复核状态分离；日期切换与实时边界纳入固定测试 |

## 保留但必须明确边界

### 运营看板

默认 `operations_sandbox` 仍是确定性合成的港口业务夹具，用于页面、问答流程和
接口契约测试。公开网络上没有可合法替代现场TOS、PCS、EMS、EAM、VTS和闸口
数据的通用实时数据集，因此项目不会拿建筑能源数据伪装成港口实时态势。

生产切换点已经存在：`XIAOYI_PORT_DATA_MODE=live` 和只读 `port-ops.v1` 网关。
网关未返回 `live_data_verified=true` 或版本不兼容时，服务拒绝把结果标记为生产实绩。

### 港航知识库

知识库包含项目原创整理材料、官方页面摘要和来源目录，不宣称全球完整。来源类型、
辖区、内容范围、复核日期和发布方条款由 `data/source_registry.json` 管理。MIT许可证
只覆盖本项目代码和原创内容，不授予外部标准或网页的再分发权。

公开指标来自 `data/evaluation/maritime_qa_benchmark_v1.json` 的固定仓库
评测，不是模型训练数据，也没有做 LLM 微调。测试分区用于本版本发布验收且
暴露过工程缺陷，所以不能称为未经查看的独立留出集。报告只证明当前索引快照下
的检索排序、官方来源路由和拒答策略，不证明开放世界事实正确率或现场业务收益。

### 跨系统与本机启动器

跨系统能力、数字孪生和航行模拟器启动器是可选的本机集成工具，不是本仓库算法
成立的前提。GitHub默认全部离线。它们不应部署到公网，也不得接受任意路径或命令。

## 代码已具备、但部署方仍必须完成

1. 由组织身份平台签发短时JWT，或替换为经审查的OIDC/JWKS验证；仓库只提供本地HS256基线。
2. 由部署环境提供TLS、密钥管理、IP白名单、集中日志、告警和经演练备份；代码中的限流不代替网关防护。
3. 多实例部署前，将SQLite、内存限流和后台训练线程替换为共享数据库、分布式限流/幂等存储和持久任务队列。
4. 对站点CSV/流数据建立字段版本、缺失值、异常值、时区和数据漂移门禁。
5. 在真实设备模型上重新标定储能容量、功率、效率、电价、碳强度与安全约束。
6. 建立离线回放、影子运行、操作员验收、回滚和分阶段上线流程。
7. 逐项复核知识库引用资料的公开发布和再分发条件。

这些事项未完成前，项目可以作为可复现研究/工程基线和只读决策辅助系统，不能作为
无人值守的生产调度或设备控制系统。
