# 小懿语言模型 RL：演示讲解与专家问答

## 两分钟讲解

“我搭建了一个面向港航多系统协作的任务环境。用户给出目标后，1.7B 语言模型读取当前状态，在登记的工具和参数候选中选择下一步。运行器负责调用实际接口、保存证据和检查结果，再把反馈交回模型。

“训练分两步。第一步用正确示例做 SFT，让模型初步学会流程。第二步让它多次尝试同一个任务，用环境中的实际完成情况、参数错误和无效操作计算回报，再更新模型内部的 LoRA 参数。这次在本机 CPU 上训练了 229,376 个参数，分别保留了 SFT 和 RL 检查点。

“评测有四组：完整规则、原始模型、SFT、SFT 加 RL。它们使用同样的工具、任务和步数预算。RL 的额外效果主要看后两组之差。图中包含全部失败案例，也单独检查了故障恢复和少量基本问答。分数以实测为准，参数发生变化不等于性能一定提高。

“最后通过可见的任务入口连接本机原系统。报告包含实际返回的数据、参数和执行记录。当前是八类登记任务和公开数据、工程模拟条件下的原型验证；后续还需要更大规模、多种子、更多未知任务和实际场景的评测。”

## 经常会被追问的问题

**你训练的是大模型，还是另一个小分类器？**

策略分布取自 Qwen3-1.7B 的下一 token 输出，训练发生在最后四个 Transformer 层的 q_proj、v_proj LoRA 中。没有额外的小网络代替语言模型做决策。但本轮输出仅有 13 个动作字母，是受约束动作实验，不能据此宣称掌握自由文本工具调用。

**Harness 怎么知道该点哪个按钮、调哪个接口？**

开发者事先登记好工具名、参数和执行程序。模型选择一个候选后，运行器按登记关系调用相应 API。本轮使用系统原生 API；它没有训练鼠标坐标，也不需要逐个点击网页按钮。界面上的按钮只是给用户发起和查看任务。

**奖励是模型自己给自己打分吗？**

奖励来自可检查的环境状态：必要观测是否读取、参数是否一致、结果是否核验、状态是否恢复、是否实际完成。工具和运行器的错误会返回失败，模型说“完成了”不能直接通过检查。

**有数学理论吗？**

有。语言模型先为每个候选动作给出概率；训练尝试得到不同回报后，计算每次尝试相对组内平均水平的优势，再用策略梯度更新参数。本轮还有 KL 正则和梯度裁剪。代码采用组相对策略梯度，一组一次更新，不声称实现完整自由文本 GRPO 或提出新算法。

**没有大量人工样本，数据从哪里来？**

正确流程示例来自可复位任务环境中的参考策略；RL 轨迹来自模型实际尝试。本轮训练、验证和测试分开，留出新参数组合。合成环境能降低收集成本，但其真实性和覆盖面需要另外验证。

**为什么规则组可能比 RL 更好？**

目前工具集合和任务类别有明确边界，规则可以覆盖这些情况。模型需要有限训练才能学到相应选择，因此可能落后。只有实测的新需求适应性、维护成本、泛化或异常恢复优势，才能支持进一步价值判断。

**能证明不会遗忘其他能力吗？**

不能。本轮只有八道固定回归题，需如实呈现退步。部署时原 4B 日常模型保留，实验适配器只在实验入口使用；这保护原服务，但不是全面能力保持证明。

**以后怎样迁移到 4B？**

复用工具接口、任务环境、奖励与评测流程，用适配 4B 架构的 LoRA 重新训练。1.7B 的适配器文件不能直接当作 4B 的训练成果。

## 展示顺序

1. 先打开最终验收报告，明确哪些指令已通过、哪些没有通过。
2. 运行已验证的指令，展示模型逐步选择、实际接口结果与完整证据。
3. 展示四组对照和各类任务结果，重点解释 C→D 的变化。
4. 打开训练配置、原始轨迹、检查点与参数变化审计，说明可复现性。
5. 说明本轮范围和下一阶段需要验证的假设，不把局部结果扩展为全任务能力。
