# 小懿现在调用了哪些模型（2026-10-29）

小懿负责听懂目标和解释结果，Harness组织受控流程，各业务模型负责自己擅长的计算。当前确实接入了其他模型，其中包括强化学习策略；这些专业策略网络与聊天大模型的用途不同。

## 当前实际分工

|部分|当前状态|通俗作用|
|---|---|---|
|小懿原生成模型，约40.22亿参数|本机服务在线，沿用原权重|听懂问题、生成文字、选择工具、提出待审批计划|
|原检索嵌入模型，约5.96亿参数|本机服务在线，沿用原权重|把问题和知识资料转成可比较的向量，帮助找资料|
|RouteFinder预训练策略|隔离Linux已加载，实际推理|对容量约束的车辆运输问题生成路线，企业模式中保留为影子对照|
|PARCO预训练策略|隔离Linux已加载，实际推理|对速度和能力不同的车队分工、规划路线；研究模式通过约束检查后可参与选型|
|航行原有SAC策略|原生仿真控制器实际调用|根据船舶状态输出控制动作，执行已准入航行情景|
|港口原有PPO等、能碳SAC等策略|通过原系统训练、评测、查询和受控联动入口使用|处理各自合同定义的调度问题；状态维度、动作维度和数据集各自保留|
|小型表格RL研究|Q-learning、Double Q-learning等实验|比较服务能力档位等业务策略，记录种子、时间切分和未领先结果|
|AgentCPM规划候选|已登记和下载，当前服务离线，未启用|可选研究用语言规划器；不计入已运行模型|

OR-Tools、MPC、PID和SOP规则也参与系统，但它们分别是优化求解器、控制方法或规则基线。报告会保留这些类别，不把所有算法都称为RL。

## 一条命令怎样流转

例如：“安排这批运输任务，并核对港区负荷和能碳影响。”

1. 小懿理解目标，调用已登记能力提出计划。当前完整联合业务采用受控流程模板，业务参数和审批内容可审阅。
2. Harness检查服务、来源、权限、预算和前置条件，保存任务编号与计划摘要。
3. 运输模块让强基线和适用的预训练RL策略生成候选。
4. 主机独立检查路线是否合法：任务覆盖、车辆容量、时间窗、能量、路网等以本次合同为准。模型声称“可行”本身不算通过。
5. 企业模式按可靠基线选型；研究模式才允许合格预训练策略参与选择。RL没赢就保留基线。
6. 具体模拟业务工作单经过审批后，由原系统执行、读回结果、核验和补偿，Flutter客户端另行签收。

目前RL作用于运输、航行和调度等**业务决策层**。Harness自身的工具选择和执行调度主要由受控逻辑与语言模型规划协同完成，尚未对整个Harness进行端到端RL训练。

## 已有的一次实际记录

研究任务 `jm-2214c578e09b426a973692e13d80e751` 的30作业异构车队比较：最近邻482.69秒，OR-Tools415.44秒，PARCO267.72秒；三个候选都通过独立约束检查，随后采用PARCO。真实Flutter网页客户端已经签收同一任务。

企业任务 `jm-fb1fde6b80534698a2c5354ccf4aa5d2` 采用OR-Tools的4551.96米方案，RouteFinder的5200.39米方案保留为影子对照。这两项任务的目标单位分别为秒和米，不能互相排名。这些结果来自本机声明的工程场景，不代表现场港口提效比例。

小懿的港口小型RL研究中，PID基线仍然领先；马六甲此次验证集选出的最好方法仍为MPC。这些不利结果保留在证据里，运输策略的成绩不会替代其他问题的验证。
